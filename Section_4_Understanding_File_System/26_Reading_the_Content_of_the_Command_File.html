📝 Beginner-Friendly Study Notes: Reading Files in Node.js

🎯 Goal: Read File Contents When It Changes

  • 📖When command.txt is modified, we want to read its contents so our app can know which command to run.
  • 🔍This card explains how to “open” a file, “read” from it, and ensure we only allocate exactly as much memory as needed.

📂 Step 1: Open the File to Get a File Descriptor

  • 🔢In most programming languages (Node.js, Python, C++), you “open” a file first, then read or write from it.
  • 🆔When you open a file, the system gives you a special number called a file descriptor—think of it like an ID for that open file.
  • 📂In app.js, inside our if (eventType === 'change') block, write: 
    const fileHandle = await fs.open('command.txt', 'r');
  • 💡The `'r'` flag means “read-only.” We plan just to read commands, not write or append.

🔒 Step 2: Remember to Close the File

  • ⚠️Every time you open a file, you must close it when done—otherwise your program can leak resources (memory).
  • ✏️Right after you finish reading, add: 
    await fileHandle.close();
  • 🧹Closing frees up that file descriptor so Node.js doesn’t keep it “in use” forever.

🧐 Step 3: Look at the FileHandle Properties

  • 🔍If you log fileHandle to the console, you’ll see an object with:
    • fd: the numeric file descriptor (ID).
    • Methods like read(), stat(), and close().
  • 📚This FileHandle class is part of Node.js’s fs/promises API. It lets us perform actions (read, write, stat) using promises.

📏 Step 4: Get the File Size Before Reading

  • 📊Instead of guessing how big a buffer to allocate, we first ask the file’s size.
  • 📝Use: 
    const stats = await fileHandle.stat();
const fileSize = stats.size; // e.g., 11 bytes
  • 🔢stats.size tells us exactly how many bytes are in command.txt right now.
  • 💡Allocating a buffer that is too big wastes memory. Too small, and we miss data. Getting stats.size ensures it’s “just right.”

🧱 Step 5: Allocate a “Just-Right” Buffer

  • 📦Buffers in Node.js are like arrays of raw bytes. To create one, use: 
    const buffer = Buffer.alloc(fileSize);
  • 🔢If fileSize is 11, this buffer is exactly 11 bytes long.
  • 👍Now we won’t waste extra memory or lose data—our buffer is “just right.”

📥 Step 6: Read File Contents Into the Buffer

  • ⚙️To read, call: 
    const { bytesRead, buffer: dataBuffer } =
  await fileHandle.read(buffer, 0, fileSize, 0);
  • 🔍Arguments explained:
    • buffer: which buffer to fill.
    • 0 (offset): where in buffer to start storing bytes (start at index 0).
    • fileSize (length): number of bytes to read (the whole file).
    • 0 (position): read starting at the beginning of the file.
  • 📦bytesRead tells how many bytes were actually read (should match fileSize).
  • 🖋️dataBuffer now contains the raw bytes; we can convert it to a string: 
    const contentText = dataBuffer.toString('utf8');

⚠️ Step 7: Why Some Reads Return Zero Bytes

  • 🔄If you call read() a second time without changing position, Node starts from where it left off (end of file).
  • ❓Reading again returns bytesRead = 0 because there’s nothing new past the end.
  • 💡By always specifying position = 0, we force each read to start from the file’s beginning—so we get all bytes every time.

🔗 Step 8: Complete Code Example

  • 📝Inside your if (eventType === 'change') block, you can write: 
    (async () => {
  // 1) Open file in “read” mode
  const fileHandle = await fs.open('command.txt', 'r');

  // 2) Get file size
  const stats = await fileHandle.stat();
  const fileSize = stats.size;

  // 3) Allocate a buffer that’s exactly fileSize bytes
  const buffer = Buffer.alloc(fileSize);

  // 4) Read into buffer from the start of the file
  const { bytesRead, buffer: dataBuffer } =
    await fileHandle.read(buffer, 0, fileSize, 0);

  // 5) Convert raw bytes to a string command
  const contentText = dataBuffer.toString('utf8').trim();
  console.log('Command received:', contentText);

  // 6) Close the file to free resources
  await fileHandle.close();
})();
  • 🎉Every time you save command.txt, this code:
    • Opens it,
    • Checks its size,
    • Reads exactly that many bytes,
    • Prints the text you typed,
    • Closes the file.

💡 Why Allocate Exact Buffer Size?

  • ⚖️Efficiency: A buffer that’s too big wastes memory; too small loses data.
  • 🚫Avoid leaks: Always close file handles to free up that numeric descriptor for other operations.
  • 🔄Consistent reads: Forcing position = 0 ensures you always read the full contents, even if someone saved without changing text.

📋 Recap & Next Steps

  • ✅We learned how to:
    • Open a file with fs.open(),
    • Get its size with fileHandle.stat(),
    • Allocate a buffer exactly that size with Buffer.alloc(),
    • Read data into the buffer with fileHandle.read(),
    • Convert bytes to text using toString('utf8'),
    • And close the file using fileHandle.close().
