📝 Node.js File APIs – Study Notes

📂 Three Ways to Handle File Operations

  • 🔹Promises API – Modern and clean to use. Supports async/await.
  • 🔹Callback API – Traditional method; uses a function that executes when the task completes.
  • 🔹Synchronous API – Performs operations immediately and blocks other code until finished.

💡All three produce the same result: working with files. They differ only in how they run behind the scenes.

🚀 Promises API

  • ✨Uses fs.promises, for example: 
    await fs.promises.copyFile("source.txt", "dest.txt");
  • 😊Easy to read and write because you can use async/await.
  • 🔄Does not block other parts of your code while waiting for the operation (non-blocking).
  • 👍Recommended for most situations because it is clean and maintainable.

➿ Callback API

  • 🛠️Uses functions like fs.copyFile("source.txt", "dest.txt", (err) => { … }) with a “callback” as the last argument.
  • ⚙️Write code that calls a function when the file operation finishes:
    • fs.copyFile("source.txt", "dest.txt", (err) => {
  if (err) {
    console.error("Error:", err);
  } else {
    console.log("Copy Complete!");
  }
});
  • ⏩Faster than the Promise version in some scenarios—when performance is critical.
  • ⚠️Can lead to “callback hell” if many nested callbacks appear—harder to maintain without proper structure.

⏱️ Synchronous API

  • ⌛Uses functions ending in “Sync,” such as fs.copyFileSync("source.txt", "dest.txt").
  • 🚫Blocks the entire application while the file operation completes—no other code runs during that time.
  • 🔒Useful only in specific cases, like reading a configuration file before the app starts, when you must get data before proceeding.
  • ❗If an error occurs, the entire process stops immediately; there’s no error handling unless you explicitly add it.

🤔 How to Choose the Right API?

  • 1️⃣Promises API – Use most of the time because it’s easy to read, non-blocking, and handles errors with try/catch.
  • 2️⃣Callback API – Use when performance is extremely critical. Be cautious of nested callbacks.
  • 3️⃣Synchronous API – Use only when you truly need to block everything (e.g., reading config before starting the server).
  • 💡In many applications, 90% of the time, the Promises API is the most practical and easiest to use.

🏁 Key Takeaways & Next Steps

  • 📌Three methods: Promises (modern), Callbacks (traditional), and Sync (blocking).
  • 📖The Promises API is the easiest to read with async/await and does not block other work.
  • ⚡The Callback API can be fastest in some scenarios but may be hard to read if excessive nesting occurs.
  • ⏳The Sync API is not recommended for normal operation because it freezes the entire application while working with files.
