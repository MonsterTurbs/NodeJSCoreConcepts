📝 Files & Node.js – Study Notes

📂 What Is a File?

  • 💾A file is a sequence of bits (zeros and ones) stored on your device.
  • 🔍How you read those bits depends on the file’s type, which tells you how to “decode” them.
  • 🖼️For example, the same bits might mean a text character in a text file, but a color and pixel position in an image file.

💾 Everything Is a File

  • 🖥️Your hard drive (or SSD, USB, etc.) acts like a big bookshelf, and each “book” is a file.
  • 📚Every photo, video, song, and document you see is stored as a file made of bits.
  • ⚙️Even your operating system and apps are collections of executable files that the computer runs directly.

📝 File Metadata (Inode)

  • 📛Name: The human-readable label (e.g., report.txt or image.png).
  • 🔒Permissions: Who can read, write, or run the file (you, other users, or programs).
  • 🗺️Location/Path: The folder structure where the file lives (e.g., /Users/me/Documents or C:\Users\Me\Documents).
  • 📊Type: Indicates how to interpret the bits—text, image, video, executable, etc.
  • ⏰Timestamps: When it was created, last modified, or last opened.

🔍 Finding Files on the Command Line

  • 💻Open a terminal (macOS/Linux) or Command Prompt (Windows).
  • 📂Use ls (macOS/Linux) or dir (Windows) to list files in the current folder.
  • 🔎Use which mkdir (macOS/Linux) or where mkdir (Windows) to locate the mkdir program file.
  • ⚙️That path (e.g., /bin/mkdir) shows you that mkdir is itself an executable file your OS runs directly.

⚙️ Executable Files & Apps

  • ▶️An executable file contains machine code that your OS can run directly (no decoding needed beyond loading).
  • 📦On macOS, apps look like a single icon, but they are actually “packages” of many files (double-click → package → lots of files inside).
  • 🔐Your OS only “knows” how to run executables; other files (images, videos) need specialized programs to decode and display them.

🔌 How Node.js Handles Files

  • 🔧Node.js is a server-side JavaScript runtime that uses the built-in fs module to work with files.
  • 📖fs.readFileSync('file.txt') reads raw bytes (a Buffer) from file.txt.
  • 🔄Convert that Buffer to text with buffer.toString('utf8') so you can see the actual characters.
  • ✍️fs.writeFileSync('file.txt', data) creates or overwrites a file with new content.
  • ➕fs.appendFileSync('file.txt', extraData) adds data to the end of an existing file.
  • ❌fs.unlinkSync('file.txt') deletes a file, and fs.renameSync('old.txt', 'new.txt') changes its name.

💡 Why Learn File Handling?

  • 📑Web and server apps often need to read configurations, save user uploads, or log activity to files.
  • ⚙️Understanding how your OS stores data (bits + metadata) helps you use fs safely and efficiently.
  • 🔄Node.js offers both synchronous (blocking) and asynchronous (non-blocking) file operations to suit different performance needs.
  • 🔐Proper file handling prevents bugs, data corruption, and security vulnerabilities in your application.

➡️ Key Takeaways & Next Steps

  • 🏆A file is a collection of bits; its “meaning” depends on the type and decoding method.
  • 🌐Everything on your computer—documents, apps, system files—is stored as a file with associated metadata (name, permissions, timestamps).
  • 🔧Node.js’s fs module provides easy ways to read, write, rename, append, and delete files using JavaScript.
  • 🚀Next, explore how files are laid out in the operating system (storage blocks, inodes) and practice both asynchronous and synchronous fs methods.
  • 🔍Then, build small projects:
    • Create a “file watcher” that automatically responds when a file changes.
    • Practice error handling (e.g., file not found, permission denied).
    • Experiment with reading/writing JSON or CSV data to store simple databases.
