📝 Beginner-Friendly Study Notes: Watching Files in Node.js

👋 Introduction

  • 🔰In this lesson, we’ll build a small Node.js app that “watches” a file and reacts whenever it changes.
  • 📂You need two files: app.js (for our Node.js code) and command.txt (where you’ll type commands).
  • 🎯The goal is to detect when command.txt is saved or modified, then read its content and run instructions.

📁 Step 1: Create Project Folder + Files

  • 📂Create an empty directory anywhere on your computer (e.g., file-watcher-app).
  • ✏️Inside that folder, create two new files:
    • app.js – where our Node.js code lives.
    • command.txt – where we’ll write commands to test “watching.”
  • 🚀Open the folder in your code editor so you can edit both files side by side.

📦 Step 2: Import Node’s File System Module

  • 🛠️In app.js, add: 
    const fs = require('fs/promises');
  • 💡This uses the Promise-based version of fs, so you can use async/await.
  • 🔍Promise-based fs functions help avoid deeply nested callbacks—easier for beginners to read.

🔧 Step 3: Wrap Code in an Async IIFE

  • 🔄An IIFE is an “Immediately Invoked Function Expression” that runs as soon as it’s defined.
  • ⚙️Inside app.js, write: 
    (async () => {
  // All your async code goes here
})();
  • 📚This lets you use await at the top level and keeps variables scoped inside, so they don’t leak out.
  • ❗️If you’re not familiar with “scope” or IIFEs, try a quick search: “JavaScript scope IIFE” to learn more.

👀 Step 4: Watch the File with fs.watch()

  • 📖Inside the async IIFE, add: 
    const watcher = fs.watch('command.txt');
  • 🔄fs.watch() returns an async iterator. That means you can use: 
    for await (const event of watcher) {
  console.log(event);
}
  • 💬Every time `command.txt` changes (when you save), the loop runs and logs an event object.
  • 🧩An async iterator is like `for…of`, but it waits for new data asynchronously. If that’s confusing, you can use a callback-based version instead (covered in docs), but staying with async/await keeps code tidy.

📝 Step 5: Inspect Event Details

  • 🔎Run your app with: 
    node app.js
  • 🛑Because the watcher loop is “always on,” your program keeps running (it doesn’t exit immediately).
  • 📋Now open and save `command.txt` in your editor:
    • You’ll see something like: { eventType: 'change', filename: 'command.txt' }
    • If you create or delete a file, you’ll sometimes see `'rename'`. That means “some file was renamed/created/deleted.”
  • 🤔You don’t need to worry about “rename” events for now. We only care when `eventType` is **'change'**.

✔️ Step 6: Only React When File Changes

  • 🔄Modify the loop to check for `event.eventType === 'change'`: 
    for await (const event of watcher) {
  if (event.eventType === 'change') {
    console.log('command.txt was changed');
    // Next: read file contents
  }
}
  • 📂Since we passed `'command.txt'` into `fs.watch()`, we don’t need to check `filename` separately—any event is for that file.
  • 🎉Now every time you save `command.txt`, you’ll see “command.txt was changed” in the console.

⚠️ Step 7: Duplicate Change Events

  • ❗️On some platforms/editors, saving once may trigger 2–4 “change” events. This happens because:
    • Different OS file systems fire multiple events.
    • Your code editor may write a temporary file, then replace it.
  • 💡For our simple app, we can ignore duplicates—just run the same logic every time we get ‘change’. Later, we could compare the file’s “last modified” timestamp or debounce events if needed.
  • 🔧Node.js docs mention that fs.watch() is not 100% consistent across platforms. That’s normal—our app just needs to handle “extra” events gracefully.

📖 Step 8: Read and Act on Commands

  • 📚Inside the “change” block, use: 
    const data = await fs.readFile('command.txt', 'utf8');
console.log('Command received:', data.trim());
  • 🔍We call fs.readFile('command.txt', 'utf8') to get the text typed in command.txt.
  • 🌟By doing data.trim(), you remove extra spaces/newlines so you have a clean command string.
  • 🚦Next, you could parse that string to decide what action to perform (e.g., “create file,” “delete file,” etc.). In this lesson, we focus on watching—future videos add more file operations.

▶️ Step 9: Try It Out

  • 🖥️Save app.js and run: 
    node app.js
  • ✏️Open command.txt in your editor. Type something (e.g., “hello world”) and save.
  • 📢You should see in the terminal: 
    command.txt was changed
Command received: hello world
  • ✅If you save again (even with no text change), you might see the message twice—that’s normal due to duplicate events.

💡 Key Takeaways

  • 🎯fs.watch() can monitor a single file or entire directory for changes, rename, or delete events.
  • ⚙️Using the fs/promises version lets you work with async/await instead of nested callbacks.
  • 🔀An async iterator (via for await … of) loops whenever an event occurs; great for asynchronous streams of data.
  • 🛠️Duplicate “change” events can happen—make sure your logic is idempotent (safe to run multiple times).
  • 🚀Next steps: parse the text in command.txt to perform file operations (create, rename, delete, etc.).
