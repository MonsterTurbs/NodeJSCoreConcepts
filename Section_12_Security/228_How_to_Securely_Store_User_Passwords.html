🔐How Not to Store Passwords

  • ❌Plain text: NEVER store “password1234” as-is.
  • ❌Symmetric encryption: If the key leaks, all passwords are exposed.
  • ❌Simple hash (SHA/HMAC): Fast to brute-force weak/short passwords; rainbow tables.
✅How To Store Passwords
  • 🧂Salt: 16+ bytes random per user; prevents reuse/rainbow tables.
  • 🔁Slow KDF: e.g. pbkdf2 or Argon2 with ≳1 million iterations/time cost.
  • 🔒Hash + Salt: Store only salt‖hash (and KDF params).
  • ⏱️Verify: Recompute KDF ‹password, salt› and use crypto.timingSafeEqual() to compare.
⚙️Example Workflow
  • User sets password → generate 16 B salt with crypto.randomBytes().
  • Compute hash = pbkdf2(password, salt, 1e6, 32, 'sha512').
  • Save salt‖':'‖hash in database.
  • On login, split stored value → re-derive → compare with timingSafeEqual().
🚀Stronger Option
  • 🌟Argon2: Winner of 2015 PW KDF contest; built-in memory/time cost; easier safe defaults.
