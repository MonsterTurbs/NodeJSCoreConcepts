📼 Adding Compression to Your App

⚙️ 1. Why Compress?

  • Reduces bytes sent over network → faster page loads 🚀
  • Lower bandwidth usage (mobile data savings!) 📶
  • Simple switch in code or proxy gives big gains (~2–3× speedup) ✨

🧩 2. Enable in Node Code

  • Import built-in module: 
    const zlib = require('zlib');
  • For file responses (streams): 
    res.setHeader('Content-Encoding','gzip');
fs.createReadStream(path)
  .pipe(zlib.createGzip())
  .pipe(res);
  • For small JSON bodies: 
    zlib.gzip(JSON.stringify(data), (err, buf) => {
  res.setHeader('Content-Encoding','gzip');
  res.end(buf);
});
  • Adjust headers: keep original Content-Type, update Content-Encoding, Content-Length

🌐 3. Enable in Proxy (nginx / custom)

  • No code changes! Let your HTTP proxy handle it:
  • nginx example: 
    gzip on;
gzip_min_length 256;
gzip_types text/html text/css application/json application/javascript;
  • Or custom Node proxy: 
    upstream your_app { server localhost:8060; }
server {
  listen 80;
  location / {
    proxy_pass http://your_app;
    proxy_set_header Accept-Encoding "";
    gzip on;
    gzip_types text/* application/json;
  }
}

🔒 4. Best Practices & Caveats

  • Check Accept-Encoding header first → choose gzip/deflate/brotli supported by client ✅
  • Avoid compressing:
    • Already-compressed files (images, videos) 📷
    • Small responses (<256 B) – overhead may exceed benefit ⚖️
    • Sensitive payloads (authentication tokens) to prevent BREACH risk 🔐
  • Use middleware if on Express: 
    const compression = require('compression');
app.use(compression());
