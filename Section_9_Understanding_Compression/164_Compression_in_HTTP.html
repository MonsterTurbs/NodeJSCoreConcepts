📦 HTTP Compression – Beginner Notes

🌐 How It Works

  • Client sends Accept-Encoding header listing supported methods (e.g. gzip, deflate, br)
  • Server picks one (say gzip) and compresses only the body ▼
  • Response must include headers:
    • Content-Type – original type (e.g. application/json)
    • Content-Encoding – compressor used (e.g. gzip)
    • Content-Length – size of compressed body
  • Browser auto-decompresses; you only implement on server 🚀

🛠️ Server Setup

  • Proxy (e.g. nginx) – easiest: just add gzip on; in config
  • Or in Node app: 
    res.setHeader('Content-Encoding','gzip');
stream.pipe(zlib.createGzip()).pipe(res);
  • Adjust options (level, windowBits, etc.) for speed ↔ ratio trade-off ⚖️

🕵️ Browser Support

  • Check your browser’s Accept-Encoding in DevTools ▶︎ Network ▶︎ Request Headers
  • Common support:
    • Chrome: gzip, deflate, br, zstd
    • Firefox: gzip, deflate, br
    • Safari: gzip, deflate
  • Server should pick the best supported method per request 🔄

📝 Tips & Gotchas

  • If you set wrong Content-Length, client will wait forever ➡️ use chunked or correct length
  • Skip compressing already-compressed media (PNG, JPEG, MP3…) to save CPU 🚫
  • Compress responses, not usually requests (rarely needed) 🔄
  • Always benchmark on your real data & pick defaults if you need simplicity 👍
