🧵 Threads & Multithreading (Beginner)

🎯 Why Multithreading?

  • Boost performance by using all CPU cores 🚀
  • Do heavy tasks (like prime calculations) without blocking your app 🔧
  • Manage background jobs separately (e.g. logging) 📝

🔄 Processes & Threads

  • Process: A running program with its own memory space.
  • Thread: A “worker” inside a process sharing memory.
  • Every process starts with 1 main thread; you can spawn more 🧵

🛌 Process States

  • Ready: Waiting in line for CPU time ⏳
  • Running: Actively using the CPU 🔥
  • Sleep: Blocked waiting for I/O or timer 🌙

✅ Concurrency vs. Parallelism

  • 🔄 Concurrency: Many tasks make progress by quick switching.
  • 🔀 Parallelism: Multiple tasks run at the exact same time on different cores.

💡 How Threads Work

  • Each thread has its own Program Counter (PC) pointing to the next instruction.
  • OS scheduler gives each thread a time slice (quantum) on a core, then switches.
  • Threads can sleep/block for I/O, then return to Ready when event completes.

👷 Creating Threads (Why vs. Child Processes)

  • Threads are lighter & faster to spawn than full processes 🏃‍♂️
  • Share memory easily—no heavy IPC setup required 🔗
  • Ideal for dividing CPU‐heavy tasks across cores ⚙️

🧠 Key Takeaways

  • Threads = units of execution inside a process.
  • OS time-slices threads for concurrency on any CPU.
  • Parallelism needs multiple cores + multiple threads.
