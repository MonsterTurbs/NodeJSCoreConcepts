🔍 Debug & Batch Thread Pool

❗ The Crash Problem

  • Spawning many tasks at once fills scheduledTasks array ⇒ huge memory use 💥
  • Main thread blocked adding tasks, never frees up idleThreads so no workers run 🤯

🐞 How to Debug

  • Use VS Code launch.json or npm run start debug script 🛠️
  • Set a breakpoint in the loop (e.g. if (i === 20000) break;) and “Step Into” 🔎
  • Inspect scheduledTasks.length and idleThreads.length to see pool state 👀

⚙️ Batching Solution

  • Break huge loop into chunks (batches) of N tasks at a time 📦
  • After scheduling each batch, wait for those N tasks to finish before next batch ⏸️
  • Track batchTaskCount; when it hits 0, increment batch index & schedule next chunk 🔁
  • Result: memory stays low, event loop stays responsive, no crash ✔️

💡 Key Takeaway

  • Never flood thread pool at once—use batching to keep main thread and pool healthy 👍
  • Debugging with breakpoints reveals hidden queue/blocking issues 🐛
