🚀 Shared Memory vs Message Passing

💡 Why Use Shared Memory?

  • ⚡Eliminate frequent data copies → fewer memory operations
  • ⚙️Faster writes/reads via SharedArrayBuffer + typed arrays
  • 📈Great for memory-intensive tasks (big arrays) and also helps CPU tasks

🔧 Setup Shared Buffers

  • 📦Create buffers in main thread:
  • ```js const primesBuf = new SharedArrayBuffer(totalPrimes * 8); const lockBuf = new SharedArrayBuffer(4); ```
  • 🚚Pass both buffers as `workerData` to each worker

🔒 Lock & Write Safely

  • 🔑Use a mutex buffer and Atomics for safe writes:
  • ```js // in worker: lock(mutexBuf); primes64.set(generatedPrimes, writeOffset); unlock(mutexBuf); ```
  • 🧩Prevent race conditions without heavy message passing

🧮 Prime Generation Example

  • ✅CPU-heavy task but shared memory still speeds it up
  • ⏱️Original (message passing): ~1000s
  • 🚀Shared memory version: ~200s (~5× faster!)

📊 Large Array Example

  • 🗃️Worker builds big arrays of numbers
  • ⏱️Message passing: ~7s
  • 🚀Shared memory: ~2s (~3× faster!)

📝 Key Takeaways

  • 🏎️Shared memory often outperforms heavy message passing
  • 🔐Always guard writes with Atomics (locks)
  • ⚖️Balance CPU vs memory intensity to choose strategy
