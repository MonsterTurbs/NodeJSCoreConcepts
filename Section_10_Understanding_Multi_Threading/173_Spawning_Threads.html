🧵 Spawning Threads in Node.js

1️⃣ Import & Worker Constructor

  • Use the built-in module: const { Worker } = require('worker_threads'); 🛠️
  • Create a thread by pointing at a JS file: new Worker('./calc.js');

2️⃣ Isolation of Variables

  • Each thread has its own copy of globals.
    ```js // app.js (main thread) const a = 400; new Worker('./calc.js'); // calc.js: const a = 1000; console.log(a); // prints 400, not affected by calc.js ```

3️⃣ Delayed Thread Creation

  • You can spawn threads later using timers: 
    setTimeout(() => {
  new Worker('./calc.js');
}, 5000);
  • Keep thread alive with an empty event loop: setInterval(() => {}, 1000);

4️⃣ process.exit & Console I/O

  • process.exit() in a worker only terminates that thread, not the whole app.
  • Worker logs go via main thread’s stdio—if main blocks, logs wait until it’s free.

5️⃣ Spawning Many Threads

  • Threads are lighter than processes but still cost memory & time. 🚀
  • Example: spawn 4 threads in a loop: 
    for(let i=0; i<4; i++){
  new Worker('./calc.js');
}
// main CPU shows ~400% on a 4-core machine
  • Avoid spawning one thread per request—use pools instead.

6️⃣ Offloading Blocking Code

  • Bad: Blocking main thread: 
    while(true){}
setTimeout(() => fs.writeFileSync('out.txt','hi'), 3000);
// never runs until loop ends!
  • Good: Do it in a worker: 
    // in worker.js
setTimeout(() => {
  require('fs').writeFileSync('out.txt','hi');
}, 3000);

7️⃣ Key Takeaways

  • ⚙️ Spawn threads via new Worker(file).
  • 🛡️ Threads are isolated—no shared globals unless you set up messaging or shared memory later.
  • 💡 Use workers for heavy or blocking tasks, keep main thread responsive.
  • 📊 Monitor CPU & memory—too many threads can exhaust resources.
