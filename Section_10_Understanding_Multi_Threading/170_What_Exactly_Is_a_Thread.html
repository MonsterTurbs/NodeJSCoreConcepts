🧵 What Is a Thread? Beginner Guide

💡 Why Learn Threads?

  • Understanding OS scheduling helps you see how code runs.
  • Threads let you do real parallel work on multiple CPU cores.
  • Key for fast servers, background tasks, heavy CPU work.

⚙️ CPU & Process States

  • 🔵 Ready: Waiting in queue for CPU time.
  • 🟢 Running: Currently using a CPU core.
  • 🌙 Sleep: Blocked—waiting for I/O, timer, or event.

📋 Program Counter (PC)

  • Each process/thread has a PC pointing to the next instruction.
  • CPU fetches & runs one instruction at a time, then PC moves on.
  • If PC hits a blocking call, OS moves it to Sleep until event ends.

🔄 Concurrency vs Parallelism

  • 🔄 Concurrency: Many tasks appear to run “together” via fast switching.
  • 🔀 Parallelism: Two or more instructions actually run at the same instant on different cores.

👷‍♂️ What Is a Thread?

  • A unit of execution inside a process.
  • Has its own Program Counter, can sleep/ready/run.
  • Processes start with one main thread; you can spawn more.

⚖️ Threads vs Processes

  • 🆚 Process: Own memory, OS-managed.
  • 🧵 Thread: Shares process memory, lighter-weight.
  • ✅ Threads created faster & share data easily vs spawning a new process.

🔢 Core Example

  • On a 4-core CPU, 7 threads share cores by time-slicing.
  • Total CPU time ≈ 100% × 4 cores ÷ 7 threads ≈ 57% per thread.
  • All threads run concurrently; only 4 run in parallel at once.

✅ Key Takeaways

  • Threads let you split heavy work & utilize multiple CPU cores.
  • OS scheduler time-slices threads—creates concurrency even on 1 core.
  • True parallelism needs ≥ 2 cores and multiple threads.
