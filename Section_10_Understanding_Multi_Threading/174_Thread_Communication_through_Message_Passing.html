🧵 Spawning Threads in Node.js

1. Import & Create

  • Load the module: const { Worker } = require('worker_threads'); 🧩
  • Spawn a new thread pointing to a JS file:
    new Worker('./calc.js');

2. Thread Isolation

  • Each thread has its own copy of variables. They don’t share globals.
  • Main thread vs worker example: 
    // main.js
const a = 400;
new Worker('./calc.js');  // in calc.js: const a = 1000;
console.log(a);           // prints “400”

3. Timed Thread Launch

  • Delay spawning with setTimeout: 
    setTimeout(() => {
  new Worker('./calc.js');
}, 5000);
  • Keep worker alive with: setInterval(() => {}, 1000); ↻

4. process.exit & Logging

  • process.exit() inside a worker quits only that thread.
  • Worker console.log messages route through the main thread’s console.

5. Creating Multiple Workers

  • Example: spawn 4 workers dynamically: 
    for (let i = 0; i < 4; i++) {
  new Worker('./calc.js');
}
// On a 4-core CPU, total usage ~400%
  • Don’t spawn per request—use a pool for reuse.

6. Offload Blocking Tasks

  • Bad (blocks main thread): 
    while(true) {}
setTimeout(() => fs.writeFileSync('out.txt','hi'), 3000);
  • Good (in worker): 
    // worker.js
setTimeout(() => {
  require('fs').writeFileSync('out.txt','hi');
}, 3000);

7. Best Practices

  • 🛡️ Keep main thread free—offload heavy work.
  • 📊 Monitor CPU & memory: too many workers → high memory.
  • 🔄 Reuse workers (pool) vs. frequent new spawns.
