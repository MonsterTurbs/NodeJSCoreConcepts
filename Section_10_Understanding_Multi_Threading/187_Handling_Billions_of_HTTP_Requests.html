🚀 Benchmarking HTTP Routes: Study Notes

📋 Overview

  • 🎯Goal: send large numbers of HTTP requests to an endpoint and measure speed.
  • 🧰Tools: worker_threads to spawn “clients” sending requests in parallel.
  • 🔬Compare performance: single thread, multi-thread, batching, clustering.

📝 Request-Sender Script

  • ⚙️calc.js: each worker sends N requests sequentially, awaiting each before next.
  • 🔄Distributes total requests evenly: count/threads per worker.
  • ⏱️Logs start/end times to compute total duration.

💻 IO Performance & Threads

  • 🌐HTTP is I/O-bound: Node’s async model excels at handling many concurrent requests.
  • 🔄Adding threads still helps—while one thread awaits, others fire new requests.
  • 📊Example: 100 K requests—single thread took 5 s; 4 threads took ~2 s.

🧩 Batching Requests

  • 📦calc_batch.js: send requests in small groups (e.g. 150 at once), Promise.all, then next batch.
  • ⚡️One thread + batching matched multi-thread performance: Node handles I/O efficiently.
  • 🔧Batching = group many small tasks & await together (the reverse of CPU‐batching).

⚖️ Clustering for Scale

  • 🖥️Cluster mode: spawn one Node instance per CPU core (e.g. 12 cores → 12 workers).
  • 📈Example: 5 M requests—single machine, single thread ~60 s; 12 instances ~11 s.
  • 🔒Ethics: only benchmark your own servers—unauthorized load tests can be illegal!

🔍 Insights & Next Steps

  • 🛠️Use this testing to uncover hidden bugs (e.g. file-handle leaks under load).
  • 🌍Try real-world scenarios: add DB lookups, auth flows, HTTPS → further optimize.
  • 🎓Experiment on cloud VMs, compare CPU types, SSD speeds, CDN performance.
