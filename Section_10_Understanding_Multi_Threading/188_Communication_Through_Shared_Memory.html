🔗 Shared Memory Basics

📝 Message Passing vs Shared Memory

  • 📤Message Passing: each thread gets its own copy of data ⇒ extra memory + time.
  • 🔗Shared Memory: one block of memory accessed by all threads ⇒ faster, no copies.
  • ⚠️Becomes tricky: need to coordinate reads/writes by multiple threads.

💾 Setting Up Shared Memory

  • ⚙️Use a SharedArrayBuffer (raw bytes) or ArrayBuffer + Buffer.from(...).
  • 📏Create with fixed size, e.g. new SharedArrayBuffer(8) ⇒ 8 bytes.
  • 🔄Pass the buffer’s reference to each worker via workerData (no cloning!).

🔍 Reading & Writing Bytes

  • 🔢Wrap raw buffer in Node’s Buffer: const buf = Buffer.from(workerData.sharedBuffer).
  • ✏️Read/write by index: buf[i] = 255 ⇒ set byte to 255.
  • 👀Main thread sees changes automatically after workers modify buffer.

🚧 Race Conditions & Deadlocks

  • 🏁Race Condition: two threads read/update same byte ⇒ lost update.
  • 🔒Mutex/Lock: prevent simultaneous writes by “locking” region.
  • ⛔️Deadlock: thread forgets to release lock ⇒ everyone blocked.

🛠️ When to Use Shared Memory

  • ⚡️Ideal for small numeric arrays or binary data (e.g. image pixels, typed arrays).
  • 🔧Not for complex JS objects—must manually encode into bytes (strings, numbers, booleans).
  • 📚Advanced topic—use if you need very low‐latency, high‐throughput data sharing.
