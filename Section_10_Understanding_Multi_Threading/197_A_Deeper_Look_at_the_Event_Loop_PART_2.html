🌀 Event Loop Made Easy

🎬Rare Callback Order

Sometimes logs show A, B, D, C instead of the usual A, B, C, D. This happens because callbacks race to join when threads finish tasks in tiny microseconds.

🔄How It Happens

  • Main code schedules callbacks.
  • Two threads add callback C and D at slightly different times.
  • The loop picks up whichever arrives first.

🛑Don’t Rely on Order

Never write code that breaks if setTimeout and setImmediate swap places. Always assume order can change.

✅What Is Guaranteed

  • A logs before any nextTick or Promise callbacks.
  • nextTick and resolved-Promise run before other phases.

🕳️Poll & setImmediate

After I/O (like reading a file), the loop is in the poll phase. Then setImmediate always runs before timers (setTimeout) in the next tick.

⚙️Why process.nextTick()?

We use process.nextTick() to delay work until after all our code runs but before the event loop continues. Handy for ensuring listeners run after setup.

✨Sync vs Async

  • Synchronous: One thing at a time, same thread.
  • Asynchronous: Work happens on another thread or OS, callback joins later.

💡Promises & async/await

Promises and await are just nicer ways to write callbacks. Under the hood, they still use the event loop and callback queues.

🚫Blocking with await

Using await pauses only the async function, not the whole program. But big loops in await still block the main thread, so keep functions small.

🔑Key Takeaways

  • Event loop phases: timers, I/O, check, close.
  • Microtasks (nextTick/Promise) run first.
  • Don’t guess callback order; write safe code!
