🔹What Is an HTTP Method?

An HTTP method is included only in requests to tell the server what you want to do: e.g. GET to fetch data, POST to create, DELETE to remove, etc.

🔧Idempotency Explained

An operation is idempotent if calling it multiple times has the same effect as calling it once. Example:

  • deleteFilesOver1GB() → only first call deletes files; repeats do nothing ⇒ idempotent
  • deleteLargestFile() → each call deletes a new file ⇒ not idempotent

📥GET

  • Fetch a resource (no request body)
  • Response has a body
  • Idempotent: repeating returns same data, no server-state change

🆕POST

  • Create a resource or perform an action (request has body)
  • Response may have a body
  • Non-idempotent: each repeat may create a new resource

🔄PUT

  • Create or fully replace a resource (request has body)
  • Response may have a body
  • Idempotent: repeating same data keeps resource unchanged after first write

✏️PATCH

  • Partially update a resource (request has body)
  • Response may have a body
  • Can be idempotent or not (depends on update)—use for partial changes

🗑️DELETE

  • Remove a resource (URL/ID often enough; body optional)
  • Response may have a body or be empty
  • Idempotent: once deleted, repeats do nothing (resource already gone)

📄HEAD

  • Same as GET but no body in response—only headers
  • Useful for checking metadata (e.g. file size) without downloading
  • Idempotent

⚙️OPTIONS

  • Ask server which methods or headers are allowed
  • Crucial for CORS: browser sends OPTIONS preflight
  • Response includes allowed methods/headers in response headers
  • Idempotent
