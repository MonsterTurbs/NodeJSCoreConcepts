🌐Client–Server Model

• Client: device (browser, phone, etc.) that requests resources.
• Server: computer that serves resources back.
• They communicate over the network using TCP (HTTP/1.1 & 2) or UDP (HTTP/3).

🔗Establishing Connection

1. Client ↔️ Server must open a TCP connection (three-way handshake)
2. Over that connection, HTTP messages flow back and forth
3. HTTP/3 uses UDP + QUIC instead of TCP

✉️What’s a Message?

• A single HTTP exchange—from start of headers to end of body—called a message.
• Can span multiple TCP segments (chunks).

📨Request vs. Response

• Request: message sent from client to server.
• Response: message sent from server to client.
• Server can only send a response after receiving a request.

💡HTTP Message Structure


── Request ────────────────────────────────────
[Start]      Method + URL        →  e.g. GET /path
             Headers            →  metadata (Content-Type, Host…)
             [Body, optional]   →  data (JSON, files…)
             [End Marker]       →  signals end of body

── Response ───────────────────────────────────
[Start]      Status Code + Text →  e.g. 200 OK
             Headers            →  metadata (Content-Type, Length…)
             [Body, optional]   →  resource data
             [End Marker]       →  signals end of body
