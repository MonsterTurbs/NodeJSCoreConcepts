⚡️Reusing TCP Connections

After a client sends an HTTP request and the server responds:
• You can close the TCP connection (default in HTTP/1.0).
• Or keep it alive for more requests (HTTP/1.1+).

🔄Connection Header

Control the TCP connection behavior with the Connection header:

  • Connection: close → close socket after response
  • Connection: keep-alive → keep socket open for more requests

HTTP/2 & HTTP/3 are persistent by default and ignore this header.

💾Caching Responses

Browsers and servers can cache responses (e.g. CSS, images).
• Saves a copy locally (disk or memory).
• Next request for the same resource can be served without a new HTTP round-trip.

⏱️Why Keep-Alive Matters

Modern webpages often send hundreds of requests for HTML, CSS, JS, images…
• Each new TCP handshake costs milliseconds.
• Reusing connections adds up to seconds saved in page load time.

Check in browser DevTools ▶️ Network tab to see how many requests and whether connections stay open.
