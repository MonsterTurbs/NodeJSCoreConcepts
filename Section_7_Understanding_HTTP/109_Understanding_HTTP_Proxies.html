🔀 Proxies & Load Balancing – Beginner Notes

🛡️ What Is a Proxy?

  • 🔄A “middleman” server sits between clients and your real servers.
  • 📥Clients send requests to the proxy’s address.
  • 📤Proxy forwards each request to one of your backend servers and returns its response.

⚖️ Why Use Load Balancing?

  • 🚀Distribute traffic across multiple servers (scale out).
  • 🔄If one server fails, others handle requests (higher availability).
  • 💪Reduces load on each machine → better performance.

🌍 Real-World Clients

  • 💻Web browsers, mobile apps, IoT devices (e.g., smart fridge).
  • 📱All talk HTTP(S) to your proxy, no matter where they are.
  • 🛰️Proxy routes them to servers close by, hiding your infrastructure.

🔢 Simple Round-Robin Example

// list of backend servers
const backends = [
  { host:'127.0.0.1', port:9001 },
  { host:'127.0.0.1', port:9002 }
];
let idx = 0;

// inside proxy request handler
const target = backends[idx];
idx = (idx + 1) % backends.length;
// forward req to target, then pipe response back to client
  • ➡️1st request → server 0
  • ➡️2nd request → server 1
  • ↩️3rd request → back to server 0

🔧 Proxy Use-Cases

  • 🚫Block malicious traffic.
  • 🔐Handle TLS/HTTPS at proxy—keep backend simple.
  • ♻️Modify headers, add caching, inject rate limits.

📈 Scaling & Statelessness

  • 📊HTTP is “stateless”: each request independent.
  • 🤝With proxies you can add sessions or tokens (next topic) to remember users.
  • 🚀Add hundreds of servers by just listing them in your proxy config.
