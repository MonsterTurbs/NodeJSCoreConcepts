🌐 HTTP Status Codes – Beginner Notes

❓ What Are Status Codes?

  • 📩When you send an HTTP request, the server replies with a status code.
  • 🔢It’s just a number (100–599) that says “what happened” to your request.
  • 📝Only responses have codes—requests do not.

📊 Code Ranges

  • ℹ️100–199: Informational (just telling you “got it, keep going”)
  • ✅200–299: Success (your request worked!)
  • ↪️300–399: Redirection (please try another URL)
  • ⚠️400–499: Client Error (you did something wrong)
  • ❌500–599: Server Error (our server failed)

✅ 200 Range: Success

  • 200OK – General success.
  • 201Created – New item was made.
  • 204No Content – Worked but nothing to return.

↪️ 300 Range: Redirects

  • 301Moved Permanently – Resource moved; update your link.
  • 302Found – Temporary redirect.
  • 307Temporary Redirect – Method stays same.

⚠️ 400 Range: Client Errors

  • 400Bad Request – Request was malformed.
  • 401Unauthorized – Need to log in.
  • 403Forbidden – You’re not allowed.
  • 404Not Found – URL doesn’t exist.
  • 405Method Not Allowed – Wrong HTTP method used.

❌ 500 Range: Server Errors

  • 500Internal Server Error – Something broke on our end.
  • 502Bad Gateway – Upstream server failed.
  • 503Service Unavailable – Server is overloaded or down.

🎯 Why Pick the Right Code?

  • 🛠️Makes debugging easier—team members instantly know what went wrong.
  • 🔍Browsers & tools react differently (e.g. caching, redirects).
  • 🔒Security: don’t reveal too much (e.g. hide “exists” vs. “not found”).
