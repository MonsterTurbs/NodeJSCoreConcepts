📣 Understanding EventEmitter in Node.js – Study Notes

👋 Introduction

  • ✨Node.js provides a built-in object called EventEmitter.
  • ❓We’ll learn what it is, why it’s used, and how to work with it in simple terms.
  • 🚀No heavy C++ or libuv details—just plain JavaScript to manage events.

📦 Including EventEmitter

  • 📝To use it, simply write: 
    const EventEmitter = require('events');
  • 🧩This gives access to the EventEmitter class and its methods.

🏗️ Extending EventEmitter

  • 🔧Use ES6 class syntax to create your own emitter: 
    class MyEmitter extends EventEmitter {}
  • ✨Now MyEmitter has all event methods like .on() and .emit().
  • 💡Equivalent to older prototype-based inheritance, but cleaner with class.

🆕 Creating an Emitter Instance

  • 🔍Instantiate your emitter: 
    const myEmitter = new MyEmitter();
  • 🎯You can now register event listeners and emit events on myEmitter.

👂 Listening for Events (.on())

  • 🖐️Register a listener for an event named “foo”: 
    myEmitter.on('foo', () => {
  console.log('Event "foo" occurred!'); 
});
  • 🔄Each time you emit('foo'), the callback runs.
  • 🔢You can add multiple listeners on the same event; they’re invoked in order.

📣 Triggering Events (.emit())

  • 🚀Fire or “emit” the event: 
    myEmitter.emit('foo');
  • 📋If listeners exist for “foo,” they run immediately (synchronously).
  • ➕You can also pass arguments: 
    myEmitter.emit('foo', 'hello', 123);
  • 📢Listeners receive those arguments in their callback: 
    myEmitter.on('foo', (msg, num) => {
  console.log(msg, num); // logs: hello 123
});

⏱️ One-Time Listeners (.once())

  • 1️⃣.once() acts like .on() but removes listener after first execution:
    • myEmitter.once('bar', () => {
  console.log('This runs only once!');
});
myEmitter.emit('bar');
myEmitter.emit('bar'); // second time does nothing
  • 🔄The listener is automatically deleted after it runs once.

🔍 How Listeners Are Stored

  • 📦Under the hood, EventEmitter keeps a map (object) of event names to arrays of listeners.
  • 🔗Example representation: 
    {
  foo: [listener1, listener2],
  bar: [listenerA]
}
  • ➡️When you call .on('foo', fn), it pushes fn into the foo array.
  • 🔁When you call .emit('foo'), it loops through that array and calls each function.

❌ Removing Listeners

  • 🧹Use .removeListener(eventName, listenerFn) to delete a specific listener:
    • function greet() {
  console.log('Hello!');
}
myEmitter.on('foo', greet);
myEmitter.removeListener('foo', greet);
  • ⚠️If the listener is not found, nothing changes.
  • 🗑️After removal, .emit('foo') will not invoke that listener.

🔢 Checking Listeners

  • 🧐.listenerCount(eventName) returns how many listeners an event has: 
    console.log(myEmitter.listenerCount('foo'));
  • ⚙️You can also set a maximum number of listeners to catch memory leaks: 
    myEmitter.setMaxListeners(10);
  • 🚦If you add more than 10 by default, Node warns you about a “possible memory leak.”

🌳 Inheriting in Older Syntax

  • 📜Instead of class, older code might do: 
    function MyEmitter() {
  EventEmitter.call(this);
}
MyEmitter.prototype = Object.create(EventEmitter.prototype);
MyEmitter.prototype.constructor = MyEmitter;
  • 🔄Then instantiate with new MyEmitter()—works the same as ES6 class.

💡 Common Uses of EventEmitter

  • 🌐HTTP Servers: http.Server inherits from EventEmitter. Use server.on('request', ...).
  • 📂Filesystem: fs streams (e.g., fs.createReadStream()) emit events like “data” and “end.”
  • 🔧Custom Modules: Create your own modules that fire events (e.g., when a long task completes).
  • ⚙️Third-Party Packages: Many npm packages expose an EventEmitter API (e.g., readline, stream).

🔍 Built-In Source Code

  • 🌐View Node’s own events.js on GitHub: nodejs/node/lib/events.js
  • 📂It’s ~1000 lines of JavaScript—mostly extra error checks and edge-case handling.
  • ⚙️Core methods (on, emit, once, etc.) do exactly what our custom example does—store listeners in arrays and invoke them.

🛠️ Custom EventEmitter (Simplified)

  • ✍️Example code (simplified) to build your own emitter: 
    class SimpleEmitter {
  constructor() {
    this.events = {}; 
  }
  on(eventName, listener) {
    if (!this.events[eventName]) {
      this.events[eventName] = [];
    }
    this.events[eventName].push(listener);
  }
  emit(eventName, ...args) {
    const listeners = this.events[eventName] || [];
    for (const fn of listeners) {
      fn(...args);
    }
  }
  once(eventName, listener) {
    const wrapped = (...args) => {
      listener(...args);
      this.removeListener(eventName, wrapped);
    };
    this.on(eventName, wrapped);
  }
  removeListener(eventName, listener) {
    const arr = this.events[eventName] || [];
    this.events[eventName] = arr.filter(fn => fn !== listener);
  }
}
  • 🔧Create instances with new SimpleEmitter()—works like EventEmitter.
  • 🌱Good exercise to reinforce how events, listeners, and arrays tie together!

📚 Summary & Best Practices

  • 🔑EventEmitter Pattern: Register listeners with .on() or .once(), trigger with .emit().
  • 🧹Always remove listeners you no longer need (.removeListener()) to avoid memory leaks.
  • ⚠️Be cautious: Emitting events synchronously means listeners run immediately—don’t block heavy work inside listeners.
  • 💡Use .listenerCount() and .setMaxListeners() to keep track of events and prevent warnings.
  • 🚀Built-in Node modules (like http, stream, readline) leverage EventEmitter—understanding it helps use these APIs effectively.
