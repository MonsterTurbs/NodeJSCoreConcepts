🔤 Character Sets & Encodings – Beginner Study Notes

🗂️ What Is a Character Set?

  • ❓A character set is a standard that maps each human‐readable character (letters, digits, symbols) to a unique number.
  • 🔢Computers store only numbers (bits). To show text on screen, we use a character set to say “this number means ‘A’”, “that number means ‘あ’”, etc.
  • 🌐Common examples:
    • ASCII – maps 128 characters (English letters, digits, punctuation) to numbers 0–127.
    • Unicode – a vast standard covering ~149,000 characters (all world languages, emojis, symbols).
  • 📝Think: if “s” is mapped to number 115 in Unicode, then saving “s” means storing the number 115 in memory (in bits).

🔡 ASCII Character Set

  • 📜ASCII = American Standard Code for Information Interchange → covers only English letters, digits, common symbols, and control codes.
  • 🔢Total = 128 characters (numbers 0–127):
    • 0–31 → control characters (e.g., newline \n, delete).
    • 32–47 → punctuation and symbols (space, ! " # $ % & ‘ ( ) *)
    • 48–57 → digits 0–9.
    • 65–90 → uppercase letters A–Z.
    • 97–122 → lowercase letters a–z.
    • More punctuation up to 127.
  • 💾ASCII is a subset of Unicode: same numeric values for these 128 characters, but Unicode goes far beyond (other languages, emojis).
  • 📖To view the ASCII table on macOS/Linux: man ascii → lists each character with its:
    • Hex value (e.g. 0x41 for “A”)
    • Decimal value (65 for “A”)
    • Binary value (0100 0001₂ for “A”)

🌍 Unicode Character Set

  • 📚Unicode defines a universal mapping for 149,000+ characters (letters, symbols, emojis) from nearly every writing system.
  • 🔢Each character has a unique code point, e.g.:
    • “s” → U+0073 (decimal 115).
    • “あ” → U+3042 (decimal 12354).
  • 🌱Unicode grows over time (new emojis, new scripts). Version 15.1 (September 2023) already includes ~149 000 characters.
  • 🔎See full list: Unicode Consortium (just a standard, not software).

🔄 Encoders & Decoders

  • ⚙️Computers only store bits (0s & 1s). To save images, text, or audio, we use:
    • Encoder: converts human‐readable data (text, image) → bits.
    • Decoder: converts bits → human‐readable data (text, image).
  • 📷Example: Image encoder turns a photo into a JPEG file (bits). A JPEG decoder (e.g., your phone’s photo app) converts bits back into the picture you see.
  • 📜For text, character encodings map between characters ↔ sequences of bytes (bits). Without encoding, terminals can’t show letters!

🔤 What Is a Character Encoding?

  • 💾A character encoding assigns each character to a specific byte sequence (eight bits or more) so computers can store and transmit text.
  • 🌍Common encodings:
    • UTF-8 → the most popular today, covers all of Unicode. Uses 1–4 bytes per character.
    • UTF-16 → another Unicode‐based encoding, uses 2 or 4 bytes per character.
    • ISO-8859-1 (Latin-1) → old standard for Western European languages (1 byte per char, covers 256 codes).
  • 🔑Example in UTF-8:
    • “s” → decimal 115 → binary 01110011₂ (one byte, because ASCII subset).
    • “😊” (emoji) → large code point → becomes 4 bytes: 11110000 10011111 10010000 10011110₂.
  • 🚨If you decode bits with the wrong encoding (e.g., read UTF-16 bytes as UTF-8), you see garbled text (“�” or weird symbols).

🧩 How UTF-8 Works

  • 🎯UTF-8 stores each Unicode code point as 1–4 bytes:
    • 1 byte for ASCII subset (0–127): most common English characters.
    • 2 bytes for many Latin, Greek, Cyrillic characters, etc.
    • 3 bytes for most CJK (Chinese/Japanese/Korean) characters.
    • 4 bytes for emojis, historical scripts, rare symbols.
  • 🔍Example: Lowercase “s” (Unicode U+0073) → 01110011₂ (1 byte). 11510 = 0x73 in hex.
  • 💡All ASCII characters have a leading zero in UTF-8, so any value <128 is just that byte.
  • ✨Many other characters need 2–4 bytes. E.g., “あ” (U+3042) → E3 81 82 (3 bytes).

🔗 ASCII & UTF-8 Relationship

  • 📦ASCII is a subset of UTF-8:
    • ASCII characters (0–127) always encode as a single byte in UTF-8.
    • Example: “A” = 6510 = 01000001₂ = 0x41. That same byte appears in UTF-8.
  • 🎨So any pure-ASCII text is automatically valid UTF-8.
  • ⚠️If you mix ASCII with other languages in UTF-8, ASCII bytes stay as-is; non-ASCII use multi‐byte sequences.

🔍 Viewing Code Points in Calculator

  • 🧮Use your Programmer Calculator to see how numbers map to characters:
    • Select Dec mode and enter 115. ↓ The calculator’s char viewer shows: “s” (ASCII/Unicode).
    • Switch to Hex: you see 0x73. That same 0x73 in UTF-8 → 01110011₂ as a single byte.
  • 👀To confirm: man ascii (macOS/Linux) lists ASCII codes in octal, hex, and decimal. Scroll to 115 → letter “s”.

❗ Why Encodings Matter

  • 🌐Without correct encoding, text becomes gibberish (e.g., reading UTF-16 bits as UTF-8 outputs “�”).
  • 📧Web pages, APIs, and databases often specify “charset=UTF-8” so everyone decodes bytes the same way.
  • 🔑As a back-end engineer, you’ll handle text in data storage & network: always confirm encoding to avoid bugs!

🔧 Checking File Encoding

  • 💻On macOS/Linux, use file command to inspect a text file’s encoding:
    • file myfile.txt → shows something like “UTF-8 Unicode text” or “ASCII text”.
  • 🔄On Windows, many editors (Notepad++, VS Code) display file encoding at the bottom right. You can convert between encodings there.
  • 📘Always save new source files as UTF-8 (with BOM off) unless you have a special reason.

⚠️ Common Pitfalls & Tips

  • ⛔Mixing encodings: Storing UTF-8 bytes in a system expecting ISO-8859-1 leads to broken characters (e.g., “ã©” instead of “é”).
  • 🔄Always specify encoding when reading/writing text (e.g., in Node.js: fs.readFile('file.txt', 'utf8', ...)).
  • 🔍If you see “�” (replacement character), it means the byte sequence didn’t match a valid code in the chosen encoding.
