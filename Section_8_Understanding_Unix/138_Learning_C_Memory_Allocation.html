🧠 Memory Allocation in C

📦 Stack vs. Heap

  • Stack: Auto‐managed, small (MBs), variables live only inside functions.
  • Heap: Manually managed with malloc()/free(), large (GBs).
  • Use heap when you need big or dynamic memory at runtime. 🌱

🔗 malloc() & free()

  • Reserve N bytes on the heap: int *p = malloc(12); (12 bytes → 3 ints if each is 4 bytes)
  • Always free(p); when done to avoid memory leaks. 🚰
  • malloc() returns a pointer (address)—you index like an array:
for(int i=0; i<3; i++){
  p[i] = i*10;    // store in each 4-byte slot
}
for(int i=0; i<3; i++){
  printf("%d\n", p[i]);
}

🧮 Bytes & Binary

  • Every variable’s bits ≔ zeros & ones. 1 byte = 8 bits. 🎯
  • See exact bit patterns at Simon’s types-convert.
  • Example: storing int a = 3500; uses 4 bytes → specific 32-bit pattern.

🔄 Typecasting Pointers

  • You can reinterpret the same bits as different types with casts:
int *pi = malloc(4);
*pi = 500;
char *pc = (char*)pi;
printf("%c\n", pc[0]);   // reads first byte as a char
  • ⭐ Treats pointer pi (an int*) as char*.

🌐 C vs. JavaScript

  • C: Scalars (ints, floats) are bits; objects/arrays use heap & pass pointer → fast.
  • JS: Primitives (numbers) copied by value; objects/arrays passed by reference (under-the-hood pointers).
  • In C you control & free heap; JS hides malloc/free inside engine. 🤖

✅ Key Points

  • 🚀 Use malloc(N) for large/dynamic data → returns pointer.
  • 🔒 Free heap with free() when done.
  • 📐 Bits belong to stack (auto) or heap (manual) regions.
  • 🔄 Cast pointers to reinterpret raw bytes as different types.
