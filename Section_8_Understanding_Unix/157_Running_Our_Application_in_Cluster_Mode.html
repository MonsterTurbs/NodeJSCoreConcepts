🎓 Video App: Cluster Mode

1️⃣ Why Cluster? ⚙️

Use all CPU cores by running multiple Node workers. Ensures high throughput for uploads, downloads, and light APIs.

2️⃣ cluster.js Setup 📂

const cluster = require('cluster');
if (cluster.isPrimary) {
  const cores = require('os').availableParallelism();
  for (let i=0; i<cores; i++) cluster.fork();
} else {
  require('./index');
}

3️⃣ Primary vs Worker 🤝

  • Primary: forks workers, holds the JobQueue, coordinates heavy tasks.
  • Worker: runs Express/API (index.js), sends “resize” requests to primary via process.send().

4️⃣ Message Passing ✉️

// In worker (Video.js controller)
process.send({
  type:'new_resize',
  data:{ videoId, width, height }
});

// In primary (cluster.js)
cluster.on('message', (worker,msg)=> {
  if (msg.type==='new_resize') {
    jobs.enqueue({type:'resize',...msg.data});
  }
});

5️⃣ Handle Worker Exit 🔄

cluster.on('exit', (worker, code, signal)=> {
  console.log(`Worker ${worker.process.pid} died (${code||signal}), restarting`);
  cluster.fork();
});

6️⃣ Single-Process Fallback 🔀

Allow “node index.js” too—no process.send errors—by initializing JobQueue only when cluster.isPrimary.

7️⃣ Scaling Beyond One Machine 🌐

Deploy on multiple servers: each can run cluster mode. All resizing still central in primary per server; combine via load-balancer for global scale.
