🔗 Massive Communication App: C Part

🚀 Goal Overview

  • Build number_formatter.c to read numbers from stdin, format them, and write to a file.
  • Integrate with Node.js: app.js reads a source file and pipes its data into the C program.

📥 Reading One Character

Use fgetc() to grab one byte from stdin:

int c = fgetc(stdin);
  • Returns the character (as an int!) or EOF.
  • Loop to keep reading:
while (c != EOF) {
  // process c
  c = fgetc(stdin);
}

⌨️ End-Of-File (EOF)

  • EOF signals “no more data”.
  • In terminal press Ctrl +D to send EOF.
  • C auto-flushes open streams before exiting main().

📝 Redirecting & Buffering

Write output to a file:

FILE *out = fopen("dest.txt", "w");
fprintf(out, "%c", c);
fflush(out);  // optional manual flush
fclose(out);
  • Without fflush(), C buffers writes for efficiency.
  • Manually fflush() forces write-to-disk immediately.

🔄 Node ↔ C Piping

app.js:

const { spawn } = require('child_process');
const rs = fs.createReadStream('source.txt');
const fmt = spawn('./number_formatter', ['dest.txt', '$', ',']);
rs.pipe(fmt.stdin);
fmt.on('close', code => {
  console.log('Done with code', code);
});
  • Piping rs.pipe(fmt.stdin) streams data directly into the C process.
  • Low-memory & high-throughput: Node reads, C processes & writes.

🔢 Parsing Digits

  • Allocate buffer for one number: char *num = malloc(10*sizeof(char));
  • On digit (c!=' '):
      - num[idx++] = c; — accumulate
  • On space & idx>0:
      - num[idx]='\0'; — terminate C-string
      - format and fprintf(out, "%s\n", num);
      - free(num); num = malloc(...); idx=0;

💾 Memory Management

  • malloc() allocates heap memory. free() must release it.
  • Leaking malloced memory → ever-growing RAM use & crash.
  • C gives you power & responsibility; Node’s V8 GC handles most JS allocations.

🎨 Formatting Numbers

  • Call a helper: char* out = format_number(num, '$', ',');
  • Function returns a new malloced string with commas & prefix.
  • Remember to free(out) after fprintf().

⚡ Performance & Scaling

  • ✓ Stream-based: handles gigabytes in constant memory.
  • ✓ C process uses 100% CPU, Node.io ~5%; low-latency & high-throughput.
  • ✓ Works with huge files (10 GB+) without crashing.
