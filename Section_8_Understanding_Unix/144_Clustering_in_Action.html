🤖 Node.js Clustering Tutorial

1️⃣ Setup Cluster File cluster.js

▪️ Create cluster.js in your project folder.
▪️ Load the module:
const cluster = require('node:cluster'); 😊

2️⃣ Primary vs. Worker 💡

  • cluster.isPrimary is true only in the parent process.
  • Workers (children) have isPrimary === false.

3️⃣ Fork Workers 🔄

In the primary, spawn one worker per CPU core:


const os = require('node:os');
const cores = os.availableParallelism();
for (let i = 0; i < cores; i++) {
  cluster.fork();
}

4️⃣ Parent & Child Logs 📋

Distinguish each process:


if (cluster.isPrimary) {
  console.log('👑 Primary PID:', process.pid);
} else {
  console.log('🤖 Worker PID:', process.pid);
}

5️⃣ Auto-Respawn on Exit 🔁

When a worker dies, the primary can fork a replacement:


cluster.on('exit', (worker, code, signal) => {
  console.log(`Worker ${worker.process.pid} died… restart`);
  cluster.fork();
});

6️⃣ IPC: parent ⇆ worker 📨

  • Workers send messages:
    process.send({ action: 'request' });
  • Primary listens:
    cluster.on('message', (worker, msg) => { … });

Great for counting requests or coordinating tasks!

7️⃣ Starting Your Server 🚀

In workers, require your app:


if (!cluster.isPrimary) {
  require('./server.js');
}

Now each worker runs server.js listening on the same port.

8️⃣ How It Actually Listens 🕸️

The primary holds the TCP port; it shares it with workers via IPC.
Workers never bind the port directly—they receive connections from the primary.

9️⃣ Production with PM2 ✅

Use pm2 to auto-cluster & manage:
pm2 start server.js -i max
PM2 handles forks, restarts, logs & monitoring for you!
