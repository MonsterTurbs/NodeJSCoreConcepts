👶 Environment Variables in Unix & Node

🌱What Are Env Vars?

• Like regular variables (foo=bar in shell) but marked to be exported.
• Exported vars are passed from a parent process to its child processes.
• Commonly used to configure apps (e.g. MODE=production).

🖥️Defining & Viewing in Shell

# Define a normal var
MY_VAR=hello

# Export to make it an env var
export MY_VAR

# List all env vars
env

# See one
echo $MY_VAR

🔄Scope of Env Vars

  • Available only to the process that exports them and its children.
  • Not automatically inherited by new sibling shells.
  • To make persistent, put export lines in ~/.bashrc or ~/.zshrc.

📦Accessing in Node.js

// In Node
console.log(process.env.MY_VAR);

// Log all env vars
console.log(process.env);

If you run node app.js after export MY_VAR=hello, process.env.MY_VAR is "hello".

👶Passing to Child Processes

const { spawn } = require('child_process');

// By default, child.env == process.env
const cp = spawn('node', ['child.js'], {
  env: process.env
});

You can override env to pass a custom env var set.

🔧Example in C

#include <stdio.h>
#include <stdlib.h>

int main() {
  char *mode = getenv("MODE");
  printf("MODE = %s\n", mode ? mode : "undefined");
  return 0;
}

Compile & run after export MODE=staging to see it.

✅Key Takeaways

  • Use export NAME=value to share vars with child processes.
  • Read in shell: echo $NAME; in Node: process.env.NAME.
  • Env vars control config (dev vs prod) without changing code.
