🔗 Unix Data Streams Explained

🔌Three Standard Streams

  • stdin (fd 0): Input into a process (keyboard by default).
  • stdout (fd 1): Regular output from a process (screen by default).
  • stderr (fd 2): Error & diagnostic messages (screen by default).

🖥️Default Connections

• stdin → TTY (terminal reads your keyboard).
• stdout → TTY (shows on your monitor).
• stderr → TTY (also shows on monitor).

📥Reading stdin in Node.js

process.stdin.on('data', chunk => {
  console.log('Got stdin:', chunk.toString())
});

Hit Enter in terminal to send keyboard text into your script.

📤Writing stdout & stderr in Node.js

process.stdout.write('Hello stdout\n');
process.stderr.write('Warning on stderr\n');

console.log() writes to stdout with a newline.

🔗Piping Between Processes

Chain apps: app1 | app2 passes app1’s stdout into app2’s stdin.
You can link many processes: a | b | c.

💾Redirecting Output & Errors

  • command > out.txt saves stdout to file.
  • command 2> err.txt saves stderr to file.
  • command >& file (or >>) can merge streams.

🚀Streams in C

#include <stdio.h>
int main(){
  char c;
  while((c = fgetc(stdin)) != EOF){
    fputc(c, stdout);  // echo input
  }
  return 0;
}

Uses stdin, stdout like Node.js streams.

🎯Why Streams Matter

  • 🎬 Build small tools that chain together.
  • 📂 Handle gigabytes of data without big memory use.
  • 🛠️ Filter, transform, and log info flexibly.
