🤔 What Is Node.js? – Beginner-Friendly Study Notes

💻 From Machine Code to High-Level Languages

  • 0️⃣Machine Code: The CPU’s native “language”—just 0s and 1s. Different CPUs (ARM, x86, etc.) have different instruction sets.
  • 📝Assembly Language: Easier to read than raw 0s and 1s. An assembler translates it into machine code.
  • ⚙️C / C++: Mid-level languages that let you control hardware directly (files, network, memory). Use a compiler to convert into machine code.
  • 🌐JavaScript / Python: High-level languages. Normally don’t talk to hardware directly—you need an engine or runtime to bridge that gap.
  • 📚To run JavaScript on a server (reading files, handling HTTP), we need Node.js to “help” JS communicate with the hardware.

🔍 Assembly and C++ Examples

  • 🔣Assembly (Hello World): Over 20 lines of low-level code just to print “Hello World.” Requires specifying string length, exit code, etc.
  • 🚀After running through an assembler and linker, it becomes a binary executable that works on the correct CPU & OS.
  • 🖥️C++ (File Creator): Looks more like JavaScript: it asks for a filename and content, then creates the file. Behind the scenes, g++ turns it into over 8,000 lines of assembly!
  • ⚠️You can copy the final executable to another machine with the same CPU & OS—no recompilation needed.

🌐 How JavaScript Runs

  • ❓JavaScript is human-readable text, but CPUs only understand 0s and 1s.
  • ⚙️JavaScript Engine: A program that converts JS into machine code.
  • 🕷️Spidermonkey: The first JS engine by Brendan Eich (used in Firefox).
  • 🔧V8: Google’s JS engine in Chrome and Node.js. It compiles JS directly into machine code, making it very fast.

🚀 What Is the V8 JavaScript Engine?

  • 🏷️Name: V8 (open-source, high-performance engine for JavaScript & WebAssembly).
  • 💎Written in: C++. It compiles JS directly into machine code—no extra layers.
  • 🌐Used in both Chrome and Node.js (node itself includes V8).
  • 📜ECMAScript: A specification defining how JavaScript should work so all engines behave consistently.
  • 🔍Key roles of V8:
    • Providing built-in JS features (e.g., console.log).
    • Compiling JS into highly optimized machine code.
    • Enabling embedding into other C++ apps to run JS there.

🔗 Embedding V8 in a C++ Application

  • 📚In C++ code, you can #include <v8.h> and bind C++ functions into the JS world.
  • 📜Example: Suppose you write a C++ function createFile(path, content) and bind it to JS. Then in JS you can call: 
    createFile("/home/user/file.txt", "Hello!");
  • 🛠️Node.js itself is a C++ program that embeds V8 plus other libraries like libuv, OpenSSL, zlib, etc.
  • 🌱As a result, you get a full JavaScript runtime on the server side, with direct access to files, network, and more.

📂 Exploring Node.js Source Code

  • 🔍Find the code at GitHub: nodejs/node (or download from nodejs.org → Downloads → Source).
  • 🗂️Key folders:
    • deps/v8/ – V8 engine source (tens of thousands of C++ lines!).
    • deps/uv/ – libuv source (C code for async I/O).
    • src/ – C++ code that builds the node binary.
    • lib/ – JavaScript files for built-in modules (fs.js, http.js, buffer.js, etc.).
  • 🔧You can compile locally (using make or build tools) to produce the node executable.
  • 🏗️In src/node.h, you’ll see #include <v8.h> and #include <uv.h>—showing V8 and libuv are embedded.

🔌 What Is libuv?

  • 📚libuv – A C library for non-blocking I/O (files, networking, timers, etc.).
  • ⚡“Non-blocking I/O” means your app doesn’t pause while waiting for file or network operations.
  • 🔄Has a built-in thread pool (default 4 threads) for file system chores and heavy tasks.
  • 🌐Network (TCP/UDP) tasks skip the thread pool and go straight to the event loop for speed.
  • 🔧Node.js links to libuv, so JS modules like “fs” or “net” run via libuv behind the scenes.

🔄 Understanding the Event Loop

  • 🎯Node.js is single‐threaded for JS (one “main thread” + event loop) but can handle I/O on libuv threads in the background.
  • 📋Execution flow example:
    1. Program sees console.log("A") and prints “A.”
    2. Encounters fs.readFile(...), queues a read-file event, then immediately moves on.
    3. Prints console.log("C") before file I/O is done.
    4. When libuv finishes reading, the event loop invokes the callback to print “B.”
  • ⏱️Timer calls (e.g., setTimeout(fn, 0)) also queue events—so even with 0ms delay, synchronous code finishes first.
  • ⚠️Don’t block the main thread! If you run a huge for loop, it freezes your entire server until it finishes.
  • 🛑If no JS tasks or I/O events remain, the Node process exits automatically.

🚀 Why Node.js Is So Scalable

  • 📈Event-Driven, Non-Blocking I/O: While waiting on files or network, JS continues running other code—no freezing.
  • 🖥️Single JS Thread: Simpler model (avoids expensive thread-switching), with libuv threads handling heavy I/O.
  • 🌐Network I/O: Directly handled by libuv → OS-level sockets, doesn’t block the JS thread.
  • 🔧Scaling Techniques:
    • “Cluster” module to run multiple Node processes across CPU cores.
    • “Child Process” module to offload heavy tasks (e.g., complex computations) to separate processes.
  • 💡Result: Can handle thousands of connections concurrently without slowing down.
