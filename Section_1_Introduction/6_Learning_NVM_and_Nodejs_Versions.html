🔍 Node Version Types

  • 📦LTS (Long Term Support)
    • Even-numbered versions (e.g., v18, v20, v22)
    • Stable for production; supported for ~30 months
    • Receive critical bug fixes and security patches
  • 🚀Current (Latest)
    • Gets new features first
    • Supported for ~6 months only
    • Good for experimentation, not recommended for production
  • 🗓️Check support dates:
    • On nodejs.org → “Release Schedule” or “Previous Releases”
    • Example: v20 (Iron) is active LTS until April 2026
    • Next LTS: v22 (supports ~30 months starting April 2024)

📅 Release Schedule & Impact

  • 🔢Versions and Support:
    • v18 (Hydrogen) – supported until April 2025
    • v20 (Iron) – supported until April 2026
    • v22 (NextIron) – begins April 2024, supported ~30 months
  • ✅Production apps → always use Active LTS or Maintenance LTS.
  • 🔜When support ends for your version (e.g., April 2025 for v18), plan to upgrade to newer LTS (v20 or v22).
  • 🔗Visit nodejs.org → “Release Schedule” for details on every release’s timeline.

🧰 What Is NVM?

  • 💡NVM = Node Version Manager
  • 🎯Allows installing multiple Node versions side-by-side
  • 🔄Switch versions instantly with a single command
  • 🌍Works on macOS & Linux (Windows alternative: nvm-windows)

📥 Listing & Installing Versions

  • 📃nvm ls → List installed versions and show available LTS/Current
  • 🔍nvm ls-remote → Display all remote versions you can install
  • ⬇️Install a specific version:
    • nvm install 20 → Installs latest v20.x.x (e.g., v20.9.0)
    • nvm install 14.20.1 → Installs exactly v14.20.1
  • 🔍Installed versions stored under ~/.nvm/versions/node/
  • 🔢Each installed Node version has its own npm (e.g., v14 uses npm 6, v20 uses npm 10).

🔄 Switching Versions & Defaults

  • 🎛️nvm use 16 → Switches your shell to Node v16 (e.g., v16.16.0)
  • 📦Verify with node -v and npm -v
  • ⭐Set a default version:
    • nvm alias default 20 → New shells load Node v20 by default
    • After closing terminal or opening new tab, node -v shows default version
  • 🗑️Uninstall an old version:
    • nvm uninstall 20.4.0 → Removes that exact version

📂 Per-Project Node Versions

  • 📁Imagine two projects on your desktop:
    • ~/Desktop/project-1 (uses Node v18)
    • ~/Desktop/project-2 (uses Node v20)
  • 📄Create a .nvmrc file inside each project:
    • cd ~/Desktop/project-1
      echo "18" > .nvmrc (specifies “18”)
    • cd ~/Desktop/project-2
      echo "20" > .nvmrc (specifies “20”)
  • 🚀Now, whenever you enter a project folder and run nvm use (with no version), NVM:
    • Reads .nvmrc → sees “18” or “20”
    • Automatically switches to that Node version
  • 👍This ensures each project always runs on its correct Node version, preventing conflicts.

⬆️ Upgrading Node Versions

  • 🔄To upgrade from v20.4.0 → latest v20.x.x:
    • nvm install 20.9.0 → Installs newest v20.9.0
    • nvm uninstall 20.4.0 → Removes old v20.4.0
    • nvm alias default 20.9.0 → Set new default
  • 📥Verify installed versions again with nvm ls
  • ⚠️When upgrading, test your project thoroughly—some code may break on newer Node versions.

🌟 Tips & Recap

  • 🔑Always pick the right Node version for your project:
    • Production → use Active LTS (even-numbered) or Maintenance LTS
    • Experimentation → can try Current versions (odd-numbered during active period)
  • ⚙️Key NVM commands:
    • nvm ls: show installed versions
    • nvm ls-remote: show all available remote versions
    • nvm install <version>: install version (e.g., “18”, “20.9.0”)
    • nvm use <version>: switch to that version
    • nvm alias default <version>: set default version
    • nvm uninstall <version>: remove a version
  • 🏁Per-project: place a .nvmrc file with version number → just run nvm use when inside that folder.
  • 📚Continuously check nodejs.org/release-schedule to plan future upgrades.
  • 🚀Mastering NVM & Node versions ensures smooth development and deployment in real-world projects!
