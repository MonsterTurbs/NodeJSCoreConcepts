🔒Why We Need MACs

Encrypting with CTR mode is fast, but an attacker can flip bits in the ciphertext and you won’t know! You need a way to detect any tampering. 😱

✍️How a MAC Works

1. Take your ciphertext (or any message) 📄
2. Mix in a shared secret key 🔑
3. Feed both into a hash function → output is called the MAC tag 🏷️
4. Send both cipher text + tag

🕵️‍♂️Receiver Verification

• Receiver recomputes the MAC from received data + shared key.
• If the computed tag matches the sent tag → message is unmodified and from the right sender.
• If tags differ → tampering or wrong sender! 🚨

🔑HMAC: Hash-Based MAC

• Uses Hmac + a hash (e.g. SHA-256) under the hood.
• Protects against “length extension” attacks that plain hashes suffer. 🚫🔗 

const mac = crypto.createHmac('sha256', key);
mac.update(ciphertext);
const tag = mac.digest('hex');

⚙️GCM Mode: Encryption + Auth

AES‐GCM combines CTR‐style encryption with built‐in authentication via a “GHASH” tag.
You don’t compute HMAC yourself—GCM does it for you: 

const cipher = crypto.createCipheriv('aes-128-gcm', key, iv);
const tag    = cipher.getAuthTag();
// On decrypt:
decipher.setAuthTag(tag);
decipher.update(...);
decipher.final();

✅What MACs Guarantee

  • Integrity: Any bit-flip breaks the tag.
  • Authentication: Only someone with the shared key can create a valid tag.
  • No silent tampering, no impersonation—ever! 🛡️
