⚠️The Problem

  • Uploading a huge (5 GB+) file at once → Node’s memory spikes to GBs 😱
  • We opened the file handle & wrote chunks without flow control → internal buffers overflow

🎯Backpressure Concept

  • When stream.write() returns false, its internal buffer is full
  • Action:
    • Pause reading from source stream
    • Wait for 'drain' event
    • On 'drain', resume reading & writing

🛠️Implementing on Server

  • Keep one file handle & write stream per upload
  • In socket.on('data', chunk): 
    if (!fileHandle) {
  fileHandle = await fs.open(...);
  fileStream = fileHandle.createWriteStream();
}
const ok = fileStream.write(chunk);
if (!ok) {
  socket.pause();               // stop reading new chunks
  fileStream.once('drain', () => {
    socket.resume();            // resume after buffer empties
  });
}
  • On socket.on('end'), close file + reset handles

🚀Implementing on Client

  • Keep one read stream from file
  • In fileStream.on('data', chunk): 
    const ok = socket.write(chunk);
if (!ok) {
  fileStream.pause();          // stop reading file
  socket.once('drain', () => {
    fileStream.resume();       // resume when socket ready
  });
}
  • On fileStream.on('end'), socket.end() to finish upload

📊Testing & Monitoring

  • Generate a 5 GB test file (e.g. modify write-many.js count to 500 million)
  • Move it into uploader/ and run server/client
  • Watch memory in Activity Monitor/Task Manager → should stay low (~tens MB)
