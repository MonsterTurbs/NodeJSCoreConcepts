📝 Study Notes: Networking & TCP/UDP Basics

🚦 Transport Layer: Why TCP Exists

  • ⚠️Network layer may drop, duplicate, or corrupt packets.
  • 🔍TCP (Transmission Control Protocol) ensures every bit sent arrives intact.
  • 🔁Retransmits lost packets and orders them correctly using sequence & ack numbers.
  • 🔒Detects corruption via checksum; requests resend if mismatch.

📖 TCP Three-Way Handshake

  • 1️⃣ SYN: Client sends SYN packet to server to start connection.
  • 2️⃣ SYN-ACK: Server replies with SYN+ACK acknowledging receipt.
  • 3️⃣ ACK: Client sends final ACK; connection established.
  • 🔗After handshake, data can flow reliably both directions.

🔧 Key TCP Header Fields

  • 📍 Source & Destination Ports: Identify sending & receiving applications.
  • 🔢 Sequence & Ack Numbers: Track order and acknowledge packets.
  • 📏 Window Size: Flow control; how many bytes can be in-flight.
  • ✅ Checksum: Verifies header + data integrity.
  • 🏁 Flags: Indicate control signals (SYN, ACK, FIN for closing).

⚡ UDP: Fast but Unreliable

  • 🏃‍♂️UDP (User Datagram Protocol) sends datagrams without handshake.
  • ❌No retransmission on loss; no ordering or flow control.
  • ✔️Checksum only verifies data against corruption.
  • 🎥Used for video/audio streaming, gaming, DNS queries where speed matters.

📝 UDP Header Fields

  • 📍 Source & Dest Ports: Identify apps.
  • 🔢 Length: Length of header + data (16 bits).
  • ✅ Checksum: Verifies header + data integrity (16 bits).

🔀 Choosing TCP vs. UDP

  • 🔒Use TCP when data integrity and order matter (e.g., SSH, HTTP).
  • ⚡Use UDP when low latency is key and occasional loss is acceptable (e.g., VoIP).
