📝 Beginner-Friendly Study Notes: Writing Large Files with Streams

🔄 Recap: Promise, Callback, & Sync Writes

  • ⌛Using fs.promises.write() in a loop took ~8 seconds to write 1 million lines.
  • ⚡Switching to fs.writeSync() made it ~1.8 seconds, but it blocked Node’s event loop entirely.
  • 🚨Using callback-based fs.write() fired many pending operations, reordered data randomly, and used hundreds of MB of RAM—causing crashes at large scales.

🤔 Can We Go Even Faster?

  • ❓You might wonder: “Is there any way to write 1 million lines faster than ~1–2 seconds?”
  • ✅Yes—by using streams, we can significantly speed up writing and manage memory efficiently.
  • 🚀Streams let Node process data in chunks, minimizing overhead compared to looping with writes.

🛠️ Step 1: Create a Write Stream

  • 📥In Node, you get a write stream with:
    const fs = require('fs');
const writeStream = fs.createWriteStream('test.txt');
  • 📋This opens (or creates) test.txt and lets you “pipe” or “write” data in small chunks instead of blocking.

✏️ Step 2: Loop & Write to the Stream

  • 🔁Use a simple loop, convert each number to a buffer, and call writeStream.write():
  • const fs = require('fs');
console.time('streamWrite');
const writeStream = fs.createWriteStream('test.txt');
for (let i = 0; i < 1_000_000; i++) {
  const buf = Buffer.from(`${i}\n`, 'utf8');
  writeStream.write(buf);
}
writeStream.end(() => {
  console.timeEnd('streamWrite');
});
  • 📈In practice, this runs in ~270 ms—over 5× faster than the writeSync version!

📊 Step 3: Compare Execution Times

  • 🕘Promise write loop: ~8 seconds
  • ⚡Sync write loop: ~1.8 seconds
  • 🚀Stream write loop: ~0.27 seconds
  • 💥Streams are ~6–30× faster depending on method—and they don’t block the entire process.

🐏 Step 4: Watch Your Memory

  • 📊Although fast, writing so many chunks without managing backpressure caused memory to spike to ~200 MB (vs. ~50 MB in the sync version).
  • ⚠️If you bump the loop to 10 million, memory usage jumped to ~2 GB and crashed—because writes queued faster than the disk could flush.
  • 🔧We’ll fix this by handling the stream’s “drain” event to pause/resume writes and keep memory low.

💡 Why Streams Are Crucial

  • 🚀Streams allow your app to write large data sets **quickly** (hundreds of ms instead of seconds).
  • 🔒By pausing on backpressure, streams prevent runaway RAM usage and keep your program stable.
  • 🌐In real-world apps—file uploads, video processing, logs—streams let Node handle big files without running out of memory.

➡️ Next: Handle Backpressure Properly

  • 🔄Right now, we wrote millions of buffers unconditionally. Instead, check writeStream.write()’s return value:
  • 🔧 
    if (!writeStream.write(buf)) {
  // If it returns false, pause writing:
  await new Promise(resolve => writeStream.once('drain', resolve));
}
  • 🧠This ensures you only enqueue more data when the internal buffer is drained, keeping memory low (<50 MB).
  • 🎉With backpressure, you combine the speed of streams with safe memory usage—ideal for production.

✅ Summary & Takeaways

  • 📚Writing 1 million lines with plain loops (promises or sync) is slower and/or memory-heavy.
  • 🚀Using a write stream drops execution time to ~0.27 seconds, demonstrating how powerful streams are.
  • ⚠️Untamed streams can blow up memory—learn to handle backpressure (drain event) to keep RAM low.
  • 💪Once you master streams and backpressure, your Node.js apps will be fast, efficient, and capable of handling large datasets.
