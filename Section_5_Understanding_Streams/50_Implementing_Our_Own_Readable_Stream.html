📝 Study Notes: Implementing a Custom Readable Stream

⚙️ Why Create a Custom Readable Stream?

  • 🔍Built-in streams (like fs.createReadStream) work well, but you may need extra control over how data is read from a source (e.g., a file, a database, or another process).
  • ✏️By extending Node’s Readable class, you decide:
    • • How and when chunks get pulled from the source
    • • How to handle end-of-stream (signaling that no more data is coming)
    • • Custom error handling and cleanup
  • 🚀In this example, we’ll build a stream that reads fixed-size chunks from a file descriptor and emits them to consumers, mimicking fs.createReadStream behavior.

➕ Including & Extending Readable

  • 📦Import Node’s Readable base class: 
    const { Readable } = require('stream');
const fs = require('fs');
  • 🏷️Define your own class that extends Readable: 
    class FileReadStream extends Readable {
  constructor(options) {
    super(options);
    // … custom setup …
  }
  // … must implement _construct, _read, _destroy …
}
  • 🔄Inside the subclass’s constructor, call super() to set up options (e.g., highWaterMark). Save the file name for later: 
    constructor({ fileName, highWaterMark = 16 * 1024 }) {
  super({ highWaterMark });
  this.fileName = fileName;
  this.fd = null;           // file descriptor (will open later)
}

🔧 Async Setup: _construct(callback)

  • ⏳Implement _construct(cb) to open the file before any reading: 
    _construct(cb) {
  fs.open(this.fileName, 'r', (err, fd) => {
    if (err) return cb(err);
    this.fd = fd;      // Save the file descriptor
    cb();              // Signal “ready to read”
  });
}
  • 📁Node will wait for cb() before invoking _read. If you pass an error (cb(err)), the stream errors out immediately.

📥 Implementing _read(size)

  • 🔍Signature: 
    _read(size) {
  // 1. Allocate a Buffer of length “size”
  // 2. Read from file descriptor into Buffer
  // 3. Push the Buffer (or its valid slice) into stream’s buffer
  // 4. If no more data, push null to signal EOF
}
  • 📦Inside _read(size):
    • • size: Requested number of bytes to read
    • • Create a temporary Buffer.alloc(size)
    • • Use fs.read(fd, buffer, 0, size, null, …) to read from file
  • ✔️Example code: 
    _read(size) {
  const buffer = Buffer.alloc(size);
  fs.read(this.fd, buffer, 0, size, null, (err, bytesRead) => {
    if (err) {
      // Signal an error
      return this.destroy(err);
    }
    if (bytesRead > 0) {
      // Push only the bytes actually read (slice off any unused bytes)
      this.push(buffer.subarray(0, bytesRead));
    } else {
      // No more data: signal end-of-stream
      this.push(null);
    }
  });
}
  • 🔚When you call push(null), Node emits the 'end' event on the stream.

🧹 Cleanup: _destroy(err, callback)

  • ⚠️Signature: 
    _destroy(error, callback) {
  // 1. Close file descriptor if open
  // 2. Call callback(errOrNull)
}
  • 🚪Close the file descriptor (if it exists): 
    if (this.fd) {
  fs.close(this.fd, (closeErr) => {
    callback(closeErr || error);
  });
} else {
  callback(error);
}
  • 🛡️If an error occurred earlier, pass it to callback(error). Otherwise, pass any closeErr (or null).

📦 Full FileReadStream Class

const fs = require('fs');
const { Readable } = require('stream');

class FileReadStream extends Readable {
  constructor({ fileName, highWaterMark = 16 * 1024 }) {
    super({ highWaterMark });
    this.fileName = fileName;
    this.fd       = null;  // File descriptor (opened in _construct)
  }

  // 1. Async setup: open the file before reading
  _construct(callback) {
    fs.open(this.fileName, 'r', (err, fd) => {
      if (err) return callback(err);
      this.fd = fd;
      callback();
    });
  }

  // 2. Read requested bytes, push to internal buffer
  _read(size) {
    const buffer = Buffer.alloc(size);
    fs.read(this.fd, buffer, 0, size, null, (err, bytesRead) => {
      if (err) {
        // Signal error: will trigger 'error' on the stream
        return this.destroy(err);
      }
      if (bytesRead > 0) {
        // Only push the portion actually read
        this.push(buffer.subarray(0, bytesRead));
      } else {
        // End of file: signal EOF
        this.push(null);
      }
    });
  }

  // 3. Cleanup: close the file descriptor
  _destroy(err, callback) {
    if (this.fd) {
      fs.close(this.fd, (closeErr) => {
        callback(closeErr || err);
      });
    } else {
      callback(err);
    }
  }
}

module.exports = FileReadStream;

🚀 Using FileReadStream to Pipe & Process Data

  • 📂Example: Copy a file from source to destination using pipe(): 
    const FileReadStream  = require('./FileReadStream');
const fs              = require('fs');

// Create custom readable from “source.txt”
const readStream  = new FileReadStream({ fileName: 'source.txt' });
// Create built-in write stream to “dest.txt”
const writeStream = fs.createWriteStream('dest.txt');

console.time('copyTime');
readStream.pipe(writeStream);

writeStream.on('finish', () => {
  console.log('Done copying.');
  console.timeEnd('copyTime'); // Shows how fast the pipe completed
});
  • ⚙️Key points:
    • • Backpressure: pipe() handles pause/resume automatically when read buffer fills faster than write can consume.
    • • Stream Events: 'data' is emitted whenever a chunk is ready; 'end' when EOF; 'error' if any error occurs.
    • • Cleanup: On any error, pipe() will forward the error & you can handle it via readStream.on('error', …) or writeStream.on('error', …).
    • • Asynchronous Setup: _construct() ensures _read won’t run until file is opened.

📌 Best Practices & Key Takeaways

  • ⚠️Do not call or override internal methods (like _read) directly—Node manages them. Implement only the underscored methods documented (_construct, _read, _destroy).
  • 🛡️Error handling: Inside _read, use this.destroy(err) if fs.read fails. Inside _destroy, always call callback(err) so Node knows cleanup is done.
  • 🔚End-of-stream: Push null in _read to signal “no more data,” which triggers the 'end' event.
  • 💡Always call callback() (or callback(err)) in _construct and _destroy to avoid hanging streams.
  • 🔍Read Node’s stream docs to learn available options (e.g., encoding, objectMode, highWaterMark) and event names ('data', 'end', 'error', 'close').
  • 📚Use built-in fs.createReadStream in production unless you need this deep customization; Node’s implementation is battle-tested and optimized.
  • 🚀Once comfortable with custom streams, you can implement more advanced streams (e.g., Duplex and Transform) for encryption, compression, or custom protocol parsing.
