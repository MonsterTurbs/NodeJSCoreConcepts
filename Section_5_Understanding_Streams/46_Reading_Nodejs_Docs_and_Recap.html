📝 Study Notes: Readable Streams in Node.js

📚 What Is a Readable Stream?

  • 🔄A Readable Stream is a way to read data in chunks instead of loading the entire source into memory.
  • ⚙️Examples: reading large files, processing HTTP requests, or receiving data from another process (like FFmpeg).
  • 🌊“Streaming” means data flows continuously in manageable pieces, keeping memory usage low.

🔄 Two Modes: Flowing & Paused

  • 🛑**Paused Mode**: Stream is idle; no data emitted until you call methods or add listeners.
  • 🏄‍♂️**Flowing Mode**: Data events are generated automatically and delivered as soon as chunks arrive.
  • ▶️Switch to **flowing** by:
    • Adding a `data` event listener
    • Calling `readable.resume()`
    • Using `readable.pipe(dest)`
  • ⏸️Switch to **paused** by:
    • Calling `readable.pause()`
    • Removing all destinations (when piping)
  • 🔍Check mode via readable.readableFlowing:
    • `null` = no consumer (not started)
    • `true` = flowing mode
    • `false` = paused mode

📥 Consuming Data: `data` Event

  • 📦When in flowing mode, each chunk arrives via: 
    readStream.on('data', (chunk) => {
  // process chunk (Buffer or string)
});
  • ⚙️By default, `chunk` is a Buffer. To get strings, use: 
    readStream.setEncoding('utf8');
  • 🛑**Pause** with: 
    readStream.pause();
  • ▶️**Resume** with: 
    readStream.resume();
  • 🔚**End Event**: Emitted when no more data is available: 
    readStream.on('end', () => {
  // all data consumed
});

⚙️ Stream Events & Properties

  • 🔒`readable.on('error', ...)` – Emitted on read errors.
  • ❌`readable.on('close', ...)` – Emitted when underlying resource (file descriptor) closes.
  • 🛑`readable.on('pause', ...)` – Emitted when stream is paused.
  • 🔄`readable.on('resume', ...)` – Emitted when stream resumes from pause.
  • 🔊`readable.readableFlowing` – `null` / `false` / `true` indicates mode.
  • 📊`readable.readableHighWaterMark` – Size of internal buffer (default 64 KB for fs.createReadStream).
  • 📈`readable.readableLength` – Amount of data (in bytes) currently stored in buffer.

🔧 Two Ways to Read

  • 🌊**Flowing API**: Use `data` event (shown earlier). Convenient for most cases where you just process as chunks arrive.
  • 📖**Non-Flowing (Paused) API**: Use `readable` event and `read()` calls: 
    readStream.on('readable', () => {
  let chunk;
  while ((chunk = readStream.read()) !== null) {
    // process chunk
  }
});
  • ⚠️Do not mix both in the same stream; choose one style per stream to avoid confusion.

🔗 Piping: Simplified Stream Chaining

  • ➡️**Pipe Syntax**: Automatically handles data flow and backpressure: 
    readStream.pipe(writeStream);
  • 🔧Piping automates:
    • Switching to flowing mode.
    • Pausing `readStream` when `writeStream` is busy.
    • Resuming `readStream` on `writeStream`’s `drain` event.
  • 🎯Ideal for simple “read from file → write to file” tasks without manual pause/resume logic.
  • 📚Example: 
    const readStream = fs.createReadStream('source.txt');
const writeStream = fs.createWriteStream('dest.txt');
readStream.pipe(writeStream);

writeStream.on('finish', () => {
  console.log('Copy complete!');
});

📊 HighWaterMark & Backpressure

  • 📏HighWaterMark: Controls internal buffer size. Default for files: 64 KB.
  • ⚠️If writes are slower than reads, buffer fills up; backpressure is applied:
    • `readStream.pause()` is called (automatically when piping).
    • Waiting for `writeStream`’s `drain` event to resume reading.
  • 💡You can customize HWM: 
    const readStream = fs.createReadStream('file.txt', {
  highWaterMark: 32 * 1024  // 32 KB
});
  • ✅Proper backpressure avoids out‐of‐memory crashes when handling very large data.

🖥️ Readable Stream Example

const fs = require('fs');

// Using fs.createReadStream to read a large file in 64 KB chunks
const readStream = fs.createReadStream('bigFile.txt');

// Switch to flowing mode and process each chunk
readStream.on('data', (chunk) => {
  console.log(`Received chunk: ${chunk.length} bytes`);
  // Convert chunk to string if needed:
  // let text = chunk.toString('utf8');
  // process text...
});

readStream.on('end', () => {
  console.log('Finished reading file!');
});

readStream.on('error', (err) => {
  console.error('Error reading file:', err);
});

📌 Summary & Tips

  • ✅Streams read or write piece-by-piece—ideal for large data.
  • ⚙️Always choose one consumption style: Flowing (`data`) or Paused (`readable` + `read()`).
  • 🔗Use `pipe()` whenever possible to simplify backpressure handling.
  • 📏Adjust highWaterMark to tune buffer size (tradeoff between memory and speed).
  • 🔍Monitor `readableFlowing` to debug if your stream is paused or flowing.
  • 💡Remember: `end` is emitted automatically; `finish` is for write streams after `end()`.
