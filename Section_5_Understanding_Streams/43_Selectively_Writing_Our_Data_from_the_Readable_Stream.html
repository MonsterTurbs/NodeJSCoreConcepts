📝 Filtering Even Numbers from a Huge File

🔍 Context & Goal

  • 📚We have a very large file (“textGigantic.txt”) containing one billion numbers, each separated by two spaces.
  • 🎯Our goal: read the file chunk by chunk and write only even numbers to a new “dest.txt” file.
  • 💾We must avoid loading the entire file into memory—use Readable Streams with pause() and resume() to handle backpressure.

📥 Read Chunks Safely

  • 📂Open the huge file with padding to avoid VS Code crashing: 
    cat textGigantic.txt  
          prints chunks to terminal without loading all into memory.
  • ⚠️Opening in an editor crashes because it tries to load the full 10 GB into RAM.
  • 🔀Solution: use a fs.createReadStream('textGigantic.txt') to read small chunks (e.g. 64 KB each) and process one chunk at a time.

✂️ Splitting Chunks into Number Strings

  • 🔤Each chunk is a Buffer (bytes). Convert it into a string: 
    const text = chunk.toString('utf8');
  • 🧩Numbers are separated by two spaces (“ ”). So split on “ ”: 
    let parts = text.split('  ');
  • ❗Because a chunk may cut a number in half, the first and last entry in parts can be incomplete. We’ll fix those later.

🔧 Fixing First & Last Partial Numbers

  • ⏪First element fix:
    • If parts[0] is not a complete number (because chunk started midway), skip it or append it to the previous chunk’s leftover.
    • Store the incomplete tail from the previous chunk in a variable (e.g. leftover), then do: 
      parts[0] = leftover + parts[0];
  • ⏩Last element fix:
    • If the last entry parts[parts.length – 1] is partial, store it in leftover for the next chunk (don’t process it yet).
    • Trim parts so it excludes the last partial entry until it’s completed by the next chunk.
  • 🔄By passing the leftover between chunks, each split number will be complete before checking if it’s even.

🔢 Check Even & Write

  • ➗Convert each string to a number: 
    const num = Number(parts[i]);
  • ✔️Check if even: 
    if (num % 2 === 0) {
  writeStream.write(num + '  ');
}
    • “ ” (two spaces) keeps the same separator format in dest.txt.
  • 🖊️Only call writeStream.write() for evens; discard odd numbers.

🚦 Handling Backpressure

  • 🐏If writeStream.write(...) returns false, it means the writable buffer is full:
    • if (!writeStream.write(data)) {
  readStream.pause();
}
  • 🔔Listen for 'drain' on writeStream to resume reading:
    • writeStream.on('drain', () => {
  readStream.resume();
});
  • 📉This keeps memory stable (30–50 MB) even for a 10 GB file: the file is read/written in chunks without overfilling RAM.

🤝 Full Implementation Outline

  • 1️⃣Open file handles:
    const { open } = require('fs/promises');
(async () => {
  const readHandle  = await open('textGigantic.txt', 'r');
  const writeHandle = await open('dest.txt',       'w');
  const readStream  = readHandle.createReadStream();
  const writeStream = writeHandle.createWriteStream();
  • 2️⃣Initialize leftover:
    let leftover = '';
  • 3️⃣On 'data' event: 
    readStream.on('data', (chunk) => {
  // Convert buffer → string
  let text = leftover + chunk.toString('utf8');
  // Split by double-space
  let parts = text.split('  ');
  // Save incomplete tail for next chunk
  leftover = parts.pop(); // last may be partial
  // Process all complete parts
  for (let str of parts) {
    let num = Number(str);
    if (!isNaN(num) && num % 2 === 0) {
      if (!writeStream.write(num + '  ')) {
        readStream.pause(); // backpressure
      }
    }
  }
});
  • 4️⃣On 'drain' event: 
    writeStream.on('drain', () => {
  readStream.resume();
});
  • 5️⃣On 'end' event: 
    readStream.on('end', () => {
  // Process remaining leftover if any
  if (leftover) {
    let num = Number(leftover);
    if (!isNaN(num) && num % 2 === 0) {
      writeStream.write(num.toString());
    }
  }
  writeStream.end(); // finish writing
});
  • 6️⃣On 'finish' event: 
    writeStream.on('finish', async () => {
  console.log('All even numbers written to dest.txt');
  await readHandle.close();
  await writeHandle.close();
});
  • 💡Result: dest.txt contains exactly 500 million even numbers, each separated by two spaces.

🎉 Why This Works & Benefits

  • 🌊Streamed I/O: We never load the full file—only small chunks into memory at a time.
  • ⚡Efficient Filtering: Splitting each chunk into numbers and checking % 2 is fast and only writes half the numbers.
  • 🛡️Controlled Memory: Using pause() / resume() ensures memory stays ~30–50 MB, even for a 10 GB file.
  • 🚀Scalable: You can repeat this for hundreds of gigabytes or terabytes without overloading RAM.

✅ Key Takeaways

  • 🔄Always handle partial data at chunk edges (leftover management).
  • ⚖️Use write()’s return value and 'drain' event to manage backpressure.
  • 🧹Close file handles after streams finish to free resources.
  • 🎯Processing large data in a streaming fashion keeps your application responsive and memory usage low.
