📝 Beginner-Friendly Study Notes: Introduction to Node.js Streams

🌟 Why Streams Matter in Node.js

  • ⚡Node.js is famous for handling lots of data quickly without waiting—streams make that possible.
  • 🔍A stream is a way to read or write data piece by piece instead of all at once, saving memory and boosting speed.
  • 💡Understanding streams lets you build faster, more efficient applications—especially when working with large files or real-time data.

🎯 Learning Goals

  • 📚Learn how to use existing readable streams from Node.js or packages you install.
  • 💼Build your own readable streams to understand how they work under the hood.
  • 🔄Create and use Duplex streams (streams you can read from and write to).
  • 🔐Build a Transform stream to encrypt and decrypt data, learning how to manipulate raw bytes.

📖 What Is a Readable Stream?

  • 📂A readable stream lets your code “pull” data in chunks from a source (like a file or network).
  • 👂Instead of waiting for all data, you handle small pieces as they arrive—great for big files.
  • 🚀Examples:
    • Reading a large file bit by bit.
    • Receiving data from an HTTP request.

🔍 Using an Existing Readable Stream

  • 🔧Many Node.js modules (like fs.createReadStream()) already give you a readable stream.
  • 👨‍💻To use it, you attach event handlers like data (when a chunk arrives) and end (when it’s done).
  • 📋Example: 
    const fs = require('fs');
const reader = fs.createReadStream('bigfile.txt');

reader.on('data', (chunk) => {
  console.log('Got a chunk:', chunk.toString());
});

reader.on('end', () => {
  console.log('All data read!');
});

🛠️ Building Your Own Readable Stream

  • 📦Use Node’s stream module and extend Readable to create a custom stream.
  • 🔍Example steps:
    1. Import: const { Readable } = require('stream');
    2. Create a class: 
      class MyStream extends Readable {
  _read() {
    // produce data here by calling this.push(dataChunk)
    // when done, call this.push(null)
  }
}
    3. Use it: 
      const stream = new MyStream();
stream.on('data', (chunk) => {
  console.log(chunk.toString());
});
stream.on('end', () => {
  console.log('Done!');
});

🔄 What Is a Duplex Stream?

  • 🔀A Duplex stream can be both readable and writable. Think of it like a two-way pipe.
  • 📡Examples: network sockets where you send (write) and receive (read) data on the same connection.
  • 🛠️To create one, extend Duplex and implement both _read() and _write().

⚙️ Using Your Duplex Stream

  • 🔧After building a custom Duplex class, you pipe data into it and read from it:
  • 📋Example: 
    const { Duplex } = require('stream');

class MyDuplex extends Duplex {
  _read(size) {
    // push data out
  }
  _write(chunk, encoding, callback) {
    // handle incoming chunk
    callback();
  }
}

const duplex = new MyDuplex();
duplex.on('data', (chunk) => {
  console.log('From duplex:', chunk.toString());
});
duplex.write('Hello duplex!');
duplex.end();

🔄 What Is a Transform Stream?

  • 🔐A Transform stream is a special Duplex that modifies data as it passes through (like encryption).
  • 🔧To build one, extend Transform and implement _transform():
  • 📋Example skeleton: 
    const { Transform } = require('stream');

class MyTransform extends Transform {
  _transform(chunk, encoding, callback) {
    // modify chunk, then push transformed data
    this.push(modifiedChunk);
    callback();
  }
}

const transformer = new MyTransform();
transformer.on('data', (data) => {
  console.log('Transformed:', data.toString());
});
transformer.write('abc');
transformer.end();

🔒 Building an Encrypt/Decrypt Transform

  • 🔢We’ll work with raw binary data (bytes) to encrypt or decrypt:
  • 🛠️Steps:
    1. Import Transform from stream.
    2. Create EncryptStream class extending Transform.
    3. In _transform(chunk, encoding, callback), apply a simple cipher (e.g., XOR each byte with a key).
    4. Push the encrypted chunk onward.
    5. Do the reverse in DecryptStream.
  • 🎯Example outline: 
    class EncryptStream extends Transform {
  constructor(key) {
    super();
    this.key = key;
  }
  _transform(chunk, encoding, callback) {
    const out = Buffer.from(chunk.map(byte => byte ^ this.key));
    this.push(out);
    callback();
  }
}

class DecryptStream extends Transform {
  constructor(key) {
    super();
    this.key = key;
  }
  _transform(chunk, encoding, callback) {
    const out = Buffer.from(chunk.map(byte => byte ^ this.key));
    this.push(out);
    callback();
  }
}

🚀 Using Your Encrypt/Decrypt Streams

  • 🔗Pipe data through your transform: 
    const fs = require('fs');
const encrypt = new EncryptStream(42); // simple key
const decrypt = new DecryptStream(42);

fs.createReadStream('plain.txt')
  .pipe(encrypt)
  .pipe(fs.createWriteStream('encrypted.bin'))
  .on('finish', () => {
    console.log('File encrypted!');

    // Now decrypt:
    fs.createReadStream('encrypted.bin')
      .pipe(decrypt)
      .pipe(fs.createWriteStream('decrypted.txt'))
      .on('finish', () => {
        console.log('File decrypted back!');
      });
  });
  • 🎉After running this, decrypted.txt matches plain.txt, proving your transform works.

📋 Common Stream Events & Methods

  • 📌Readable events:
    • data: Emitted when a chunk is available.
    • end: Emitted when no more data.
    • error: Emitted on errors.
  • 📌Writable methods:
    • write(chunk): Write a chunk to the stream.
    • end(): Signal that no more data will be written.
  • 🔄Pipe method:
    • Connects a readable to a writable (or transform) automatically.
    • Example: readable.pipe(writable);

🔗 Putting It All Together

  • ✅First, practice using built-in readable streams (like fs.createReadStream()).
  • ✅Next, create your own Readable class to see how data is pushed out in chunks.
  • ✅Then, build a Duplex to handle both read and write behavior in one object.
  • ✅Finally, implement a Transform to encrypt/decrypt data, learning how to manipulate raw bytes.

💡 Why Streams Are Crucial

  • 🚀Without streams, Node.js would have to load entire files into memory—terrible for large data and slow performance.
  • 💾Streams allow your program to process data as it arrives, using minimal memory.
  • ⚡High-performance servers (file uploads, video processing) rely on streams to stay fast and responsive.
