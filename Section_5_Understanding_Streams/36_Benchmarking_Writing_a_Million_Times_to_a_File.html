📝 Beginner-Friendly Study Notes: Writing Large Files & Intro to Streams

🖊️ Challenge: Write a Million Lines

  • 🎯Create a file (e.g., test.txt) and write something to it one million times.
  • 🔧Use fs.promises to open the file in write mode:
    const fs = require('fs/promises');
(async () => {
  console.time('writeMany');
  const fileHandle = await fs.open('test.txt', 'w');
  for (let i = 0; i < 1_000_000; i++) {
    await fileHandle.write(`${i}\n`);
  }
  await fileHandle.close();
  console.timeEnd('writeMany');
})();
  • ⏱️This uses console.time / console.timeEnd to measure how many seconds it takes.
  • 📊On a modern laptop, this often takes around 8 seconds, but results vary by CPU speed, disk, and background processes.

📈 Observing Resource Usage

  • 💻Open your system monitor (Activity Monitor on macOS, Task Manager on Windows, or top on Linux) while running the script.
  • ⚡During execution, CPU usage hits ~100% on one core (Node.js is single-threaded). If you see “100%,” it means one core at full load on an 8-core machine.
  • 💾Memory hovers around 50 MB—mostly the overhead of Node.js plus buffers as you write. Keep an eye on “Memory” in Activity Monitor (or “RES” column in top).

⚙️ Callback & Sync Variations

  • 🅿️Promise version (as shown above) is easy to read but can be slower because each await waits for disk I/O before continuing.
  • 🔄Synchronous version (fs.writeSync) runs in ~1.6 s because it blocks the event loop until each write finishes, avoiding callbacks/promises overhead:
    • const fs = require('fs');
console.time('writeManySync');
const fd = fs.openSync('test.txt', 'w');
for (let i = 0; i < 1_000_000; i++) {
  fs.writeSync(fd, Buffer.from(`${i}\n`));
}
fs.closeSync(fd);
console.timeEnd('writeManySync');
  • ⚠️While faster, sync I/O blocks the entire Node process—no other code runs simultaneously.
  • 🎯Callback version with fs.open and fs.write can interleave many pending writes. It may finish quickly but can reorder lines and use hundreds of megabytes of memory, risking crashes if you queue too many callbacks.

🔢 Buffers: Core of File I/O & Streams

  • 📦Buffers store raw bytes in memory. Every time you call writeSync(fd, Buffer.from(...)), you create a buffer representing that string as bytes (UTF-8 by default).
  • 🧠Understanding buffers is crucial for streams—streams read or write data in buffer chunks rather than loading entire files at once.
  • 🔍If you don’t know buffers yet, pause here and learn about them before moving on to streams.

🔄 Why Move to Streams?

  • 🚀Writing 1 million lines with sync I/O blocked Node for ~1.6 s. For larger files (or continuous data), blocking would freeze your app.
  • 🌡️Callback version risked high memory (≥ 700 MB) and out‐of‐memory errors when queuing too many writes.
  • ⚡Streams let you process data in manageable chunks, controlling backpressure so memory stays low and Node remains responsive.
