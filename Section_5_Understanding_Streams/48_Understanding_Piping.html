📝 Study Notes: Converting Copy Logic to Streams & Piping

⚡ Why Switch to Streams?

  • 🔍Manual buffered loops (reading/writing chunks) work, but are more code and slightly slower.
  • 📈Streams let Node.js handle buffering, backpressure, pausing, and resuming automatically.
  • ⚙️Piping (via readable.pipe(writable)) simply connects a readable stream to a writable stream, managing flow for you.

🔨 Creating Read & Write Streams

  • 📂Use a previously opened file handle (via fs.open) or directly call:
    • const readStream  = srcHandle.createReadStream();
const writeStream = dstHandle.createWriteStream();
  • 📖Read Stream: emits 'data' events when reading chunks.
  • ✍️Write Stream: accepts writes until .end() is called.

🔗 Basic Piping

  • ➡️Connect readStream to writeStream:
    • readStream.pipe(writeStream);
  • 🛠️Under the hood, Node:
    • — Reads chunks from the source
    • — Writes each chunk to the destination
    • — Automatically pauses if the write buffer is full
    • — Resumes once drained ('drain' event)
  • ⚠️Only pipe a readable (source) into a writable (destination). Duplex/Transform streams can be chained.

✅ Knowing When Pipe Is Done

  • 🔔Use readStream.on('end', …) on the readable side:
    • readStream.on('end', () => {
  console.timeEnd('copyTime');
});
  • ⏱️Start timing before piping:
    • console.time('copyTime');
readStream.pipe(writeStream);
  • 📊When 'end' fires, the copy is complete—stop the timer!

📡 Pipe Events & Flow States

  • ▶️Flowing vs. Paused:
    • All streams start in paused mode.
    • Calling .pipe() switches to flowing.
    • Removing all pipe destinations or calling .pause() returns to paused.
  • 🔄Events:
    • readStream.on('pipe', dest): fires when piping starts.
    • readStream.on('unpipe', dest): fires if you remove a destination.
    • readable.readableFlowing: null (no consumers), true (flowing), false (paused).
  • 🔄Example: Log flow state changes:
    • console.log(readStream.readableFlowing); // null  
readStream.on('pipe',   () => console.log('Flowing? ', readStream.readableFlowing));  
readStream.on('unpipe', () => console.log('Flowing? ', readStream.readableFlowing));

🛡️ Robust Copy: pipeline()

  • ⚙️Use pipeline() from require('stream') instead of plain .pipe():
    • const { pipeline } = require('stream');

pipeline(
  readStream,
  writeStream,
  (err) => {
    if (err) {
      console.error('❌ Pipeline failed:', err);
    } else {
      console.log('✅ Pipeline succeeded!');
    }
  }
);
  • 🧹Benefits:
    • Automatically destroys source & dest on error.
    • Provides a single callback for “finished” or “error.”
    • Avoids leaks & unhandled errors common with bare .pipe.
  • ⚠️Prior to pipeline(), many used the pump package for similar behavior.

🧰 Legacy: pump Package

  • 📦Older alternative to pipeline():
    • const pump = require('pump');

pump(
  readStream,
  writeStream,
  (err) => {
    if (err) {
      console.error('❌ Pump failed:', err);
    } else {
      console.log('✅ Pump succeeded!');
    }
  }
);
  • 🔄Automatically cleans up on error, similar to pipeline().
  • 🛠️Still widely used, but pipeline() is built‐in as of Node 10+.

💻 Full Example: Copy Using pipeline()

const fs       = require('fs');
const { pipeline } = require('stream');

// 1. Create read & write streams
const readStream  = fs.createReadStream('text-gigantic.txt');
const writeStream = fs.createWriteStream('text-copy.txt');

// 2. Start timer
console.time('copyTime');

// 3. Pipe with built-in error handling
pipeline(
  readStream,
  writeStream,
  (err) => {
    if (err) {
      console.error('❌ Copy failed:', err);
    } else {
      console.log('✅ Copy completed!');
      console.timeEnd('copyTime'); // e.g., "copyTime: 500ms"
    }
  }
);

📌 Key Takeaways & Tips

  • ✅Piping simplifies connecting readable → writable streams and manages backpressure automatically.
  • 🔒Use pipeline() for built-in error handling & automatic cleanup (require('stream').pipeline).
  • ⚠️Don’t mix '.pipe()' with manual 'data'/'readable' listeners on the same stream—pick one style.
  • 📄Monitor flow state via readable.readableFlowing (null/true/false), and handle 'pipe' / 'unpipe' events if needed.
  • 🛡️In production, avoid raw '.pipe()' error pitfalls—use pipeline() or pump for robust cleanup.
