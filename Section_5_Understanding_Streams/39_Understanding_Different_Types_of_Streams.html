📝 Beginner-Friendly Study Notes: Types of Streams in Node.js

✏️ Writable Streams vs. 📖 Readable Streams

  • ✍️Writable Stream (writeable): you “write” data into it.
    • Example: fs.createWriteStream('output.txt')—you send chunks of data to this stream and it writes them to a file.
    • Used when you want to send data out (e.g., writing a large file, sending a response to a client, or piping to FFmpeg).
  • 📥Readable Stream: you “read” data from it.
    • Example: fs.createReadStream('input.txt')—you receive chunks of data from this stream and can process them (e.g., log, transform, or pipe to another writable stream).
    • Used when you want to pull data in (e.g., reading a huge file, receiving an HTTP request body, or consuming data from FFmpeg).

🔄 Examples in Action

  • 🖥️Writing to FFmpeg is using a Writable Stream:
    • You send data (video frames, commands) from Node to FFmpeg through a write stream.
  • 🔍Reading from FFmpeg is using a Readable Stream:
    • FFmpeg emits processed data (encoded video chunks) back to Node, and you consume those via a read stream.
  • 🌐HTTP Server:
    • Incoming requests are a Readable Stream (req), you read body chunks via req.on('data', …).
    • Outgoing responses are a Writable Stream (res), you write chunks via res.write(…) then res.end().
  • 💾File System:
    • Reading file: fs.createReadStream() (Readable).
    • Writing file: fs.createWriteStream() (Writable).

🔀 Duplex Streams

  • 🔄A Duplex Stream is both Readable and Writable at once.
    • Example: net.Socket for a TCP connection—you can both read incoming network packets and write outgoing packets on the same socket.
  • ⚙️Under the hood, a Duplex stream has two internal buffers:
    • One buffer for data you write to it.
    • Another buffer for data you read from it.
  • ✨You implement a custom Duplex by extending require('stream').Duplex and defining _read() and _write() methods.

🔄 Transform Streams

  • 🔧A Transform Stream is a special Duplex that modifies data as it passes through.
    • Example: You read raw data from a file, transform each chunk (e.g., encrypt or compress), and write the transformed chunk onward.
  • 📦Internally has two buffers (read and write). You implement it by extending require('stream').Transform and defining _transform(chunk, encoding, callback).
  • 🔑Common uses:
    • Data encryption/decryption (XOR, AES, etc.).
    • Compression/decompression (gzip, deflate, etc.).
    • Parsing or line‐splitting (e.g., splitting a CSV file into rows).

💡 Why Use Duplex & Transform?

  • 🔄Duplex lets you read and write on the same object—ideal for two-way communication (e.g., WebSockets, TCP sockets).
  • 🔄Transform lets you process data on the fly—you can encrypt large files chunk by chunk without loading them fully into memory.
  • ⚡Both help keep your app memory‐efficient because they handle data piece by piece and avoid huge buffers.

🔒 Simple Encrypt/Decrypt Transform

  • 🔑Imagine you have raw bytes and you want to encrypt them by XORing each byte with a key:
    • const { Transform } = require('stream');

class EncryptStream extends Transform {
  constructor(key) {
    super();
    this.key = key;
  }
  _transform(chunk, encoding, callback) {
    const out = Buffer.from(chunk.map(byte => byte ^ this.key));
    this.push(out);
    callback();
  }
}

class DecryptStream extends Transform {
  constructor(key) {
    super();
    this.key = key;
  }
  _transform(chunk, encoding, callback) {
    const out = Buffer.from(chunk.map(byte => byte ^ this.key));
    this.push(out);
    callback();
  }
}
  • 🚀Using these, you can pipe a large file through new EncryptStream(key) without loading the entire file into memory.

🔧 Inside a Writable Stream

  • 🧰A Writable stream has an internal buffer (default 16 384 bytes, called “highWaterMark”).
  • 📥Every time you call stream.write(chunk), Node pushes that chunk into the buffer.
  • 🚀When the buffer fills (≥ highWaterMark), Node writes the entire buffer in one operation to the underlying resource (e.g., file or network) and then empties the buffer—a process called draining.
  • ⚠️If you keep writing faster than it drains, memory will spike. To prevent that, check the boolean return of write():
    • If write() returns false, stop writing and wait for the 'drain' event before continuing.

📖 Inside a Readable Stream

  • 🧠A Readable stream also has an internal buffer (16 384 bytes by default).
  • ➕You push data into that buffer by calling stream.push(chunk) (e.g., when implementing a custom Readable).
  • 🔊When the buffer reaches its highWaterMark, the stream emits a 'data' event, giving you a chunk to process:
    • readable.on('data', (chunk) => {
  console.log('Got chunk:', chunk);
});
  • 🏁When no more data is coming, the stream calls push(null) and emits 'end', signaling you to finish.

✅ Key Takeaways

  • 📚Writable streams (e.g., fs.createWriteStream) buffer data until they can write a chunk out to a file or network. Watch for 'drain' to avoid memory spikes.
  • 📚Readable streams (e.g., fs.createReadStream) buffer incoming data and emit 'data' when a chunk is ready. They emit 'end' when done.
  • 🔄Duplex streams combine read/write in one object (e.g., sockets, Duplex class).
  • ✂️Transform streams let you modify each chunk (e.g., encrypt, compress) by extending Transform and implementing _transform.
  • 🚀Use the right stream type to handle data piece by piece—this keeps Node.js apps fast and memory-efficient.
