📝 Study Notes: Handling Partial Numbers in Stream Chunks

🔍 Context & Why Partial Numbers Occur

  • 📂We read a huge file (e.g., textGigantic.txt) of numbers separated by two spaces, using a Readable Stream in Node.js.
  • 🌊Data arrives in chunks (buffers) of fixed byte size (e.g., 64 KB). A chunk might split a multi‐digit number in half.
  • ⚠️Example: number “32182” could be split into “32” in one chunk and “182” in the next, causing both pieces to appear incomplete.
  • ❗If we naively split each chunk on two spaces, some partial numbers at chunk edges become incorrect (e.g., leading/trailing digits lost).

💡 Buffer & UTF-8 Basics

  • 🧩In Node.js, a Buffer is a sequence of bytes. Each element holds 8 bits (1 byte).
  • 🔢UTF-8 encoding: each ASCII character (digits, space, newline) uses exactly 8 bits (1 byte). So “3” or “ ” each occupies 1 byte in the buffer.
  • 🔍When you print a buffer, Node.js shows each byte as a two-character hexadecimal value, because 1 hex = 4 bits, so 2 hex = 8 bits.
  • 📏Chunk size (buffer length) might be 65,536 bytes (64 KB) by default. That many bytes ≈ 65,536 characters, but may cut numbers in half at boundaries.

✂️ Splitting Incomplete Numbers Example

  • 🔀Imagine chunk A ends with “... 3302” but the next chunk B starts “000182 ...”. Together they form “3302000182”, but splitting each chunk alone gives “3302” and “000182”.
  • ⚠️Chunk A’s last number “3302??” is incomplete, Chunk B’s first “??000182” is incomplete. Naive split loses digits.
  • 🔍We must detect incomplete numbers at the start/end of each chunk and stitch them together before converting to numeric values.

🔧 Detecting Partial Numbers at Chunk Edges

  • ➡️After converting chunk to a string (chunk.toString('utf8')), split by two spaces: 
    let parts = text.split('  ');
  • 🏷️The first element parts[0] may be a continuation of a number from the previous chunk. Save that as leftover and prepend it to parts[0].
  • 🔖The last element parts.pop() may be truncated. Store it in nextLeftover and do not process it until the next chunk arrives. 
    let nextLeftover = parts.pop();
  • 🔄Between chunks, carry leftover forward so each number becomes whole before checking it.

🔗 Stitching Partial Pieces Together

  • 🧵Suppose leftover from previous chunk = “3302”. New chunk starts → “000182...”. Combine: 
    const fullNumber = leftover + parts[0];
// fullNumber = "3302000182"
  • ✔️Then convert fullNumber to a Number and test evenness:
    • const num = Number(fullNumber);
if (num % 2 === 0) {
  writeStream.write(fullNumber + '  ');
}
  • ➡️After stitching, clear leftover and continue processing the rest of parts.

🖥️ Code Outline for Each Chunk

  • 1️⃣Start with leftover = '' before reading any data.
  • 2️⃣On 'data' event: 
    readStream.on('data', (chunk) => {
  // Convert to string & prepend leftover
  let text = leftover + chunk.toString('utf8');
  // Split by two spaces
  let parts = text.split('  ');
  // Save last potentially truncated piece
  leftover = parts.pop(); 
  // Process every complete part
  for (let str of parts) {
    let num = Number(str);
    if (!isNaN(num) && num % 2 === 0) {
      if (!writeStream.write(str + '  ')) {
        readStream.pause(); // handle backpressure
      }
    }
  }
});
  • 3️⃣On 'drain' of write stream: 
    writeStream.on('drain', () => {
  readStream.resume();
});
  • 4️⃣On 'end' of read stream: 
    readStream.on('end', () => {
  // Last leftover might form a full number now
  if (leftover) {
    let num = Number(leftover);
    if (!isNaN(num) && num % 2 === 0) {
      writeStream.write(leftover);
    }
  }
  writeStream.end();
});

✅ Why This Solution Works

  • 🏗️By carrying leftover to the next chunk, we ensure no digits are lost when a number is split across buffers.
  • ⚖️We only call writeStream.write() for complete even numbers, preserving correct data order.
  • 🔧The pause() / resume() pattern prevents memory overload—once the write buffer is full, we pause reading until it drains.
  • 🚀This lets us process very large files (GBs or more) with stable, low memory usage (~30 MB) and correct numeric results.

🔑 Key Points & Emoji Recap

  • 🧩Buffers hold bytes: Each byte = 8 bits = 1 UTF-8 character (ASCII).
  • ✂️Chunks split data: When streaming, a number can be cut between two chunks.
  • 🔗Stitch partial numbers: Carry the truncated tail (leftover) to the next chunk to reassemble the full number.
  • ⚠️Backpressure: If write() returns false, call readStream.pause() and wait for 'drain' before resume().
  • 🎯Filter logic: Convert each complete string to a Number; if even, write to dest.txt; else, skip.
