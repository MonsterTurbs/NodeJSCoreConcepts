📝 Beginner-Friendly Study Notes: Understanding Node.js Streams

🌊 What Is a Stream?

  • 🔍A stream is like a continuous flow of data, sent in small pieces (chunks) rather than all at once.
  • 🌐In everyday life, imagine people entering a room gradually—some arrive now, some later—until everyone is inside. That’s a stream of people, not all at once.
  • 💾In computers, streaming data means you send or receive bits of a big file in pieces, making it more memory-efficient.

🚫 Why Not Load Entire File into Memory?

  • ⚠️If you load a very large file (e.g., 10 GB) entirely into RAM, you might crash or slow down, especially on devices with limited memory.
  • 🖥️For example, mobile phones often have <1 GB of free memory. Loading a 500 MB file in one go could use half their RAM—unsafe!
  • 🔧Instead, streams let us move data in chunks (e.g., 16 KB at a time), keeping memory usage low and performance high.

📋 Copy-Paste Analogy

  • 📂Imagine copying a 10 GB file. You could:
    • 1️⃣Load all 10 GB into memory and then write—it’s fast but needs huge RAM “door.”
    • 2️⃣Copy in small chunks (e.g., 16 KB at a time) until done—slightly slower but uses minimal RAM.
  • ⚡Streams are like the second method: read a chunk, write a chunk, repeat until the file copy is complete.

📜 Node.js Defines Stream As…

  • ℹ️“An abstract interface for working with streaming data in Node.js.”
  • 💡That means any time data flows piece by piece (files, network, buffers), you’re dealing with a stream.

🔗 Real-World Stream Examples

  • 🎥Video Streaming: Netflix sends video data in small segments so you can watch immediately without downloading the entire movie first.
  • 📤File Copy: As shown above, copying large files chunk-by-chunk keeps memory usage low.
  • ⚙️Process Communication: Node.js talking to FFmpeg (video editor) by sending commands and data in chunks rather than all at once.
  • 🌐Network Requests: HTTP servers read incoming request data in chunks; responses are written in chunks to the client.

⚙️ How Streams Work in Node.js

  • 📥Readable Streams: Provide data in chunks you can “listen” for (e.g., fs.createReadStream for files or http.IncomingMessage for requests).
  • 📤Writable Streams: Accept data in chunks (e.g., fs.createWriteStream for files or http.ServerResponse for responses).
  • ↔️Duplex & Transform Streams: Readable + Writable combined (e.g., net.Socket) or data transformation (e.g., encryption/decryption).
  • 🔁You handle chunks as they arrive, process or transform them, then push them onward—no need to hold everything in memory.

📏 Default Chunk Size: 16 KB

  • 🔢Node.js uses 16 KB buffers by default when you create a read/write stream.
  • ⚖️Streams accumulate data until a 16 KB chunk is ready, then call _write() or emit a data event.
  • 🚀This balance of chunk size keeps speeds high while keeping memory use moderate.

🚀 First Stream Example: Writing 1 Million Lines

  • ✍️Instead of calling writeSync a million times, use fs.createWriteStream, then loop and write() buffers:
    • const fs = require('fs');
console.time('streamWrite');
const ws = fs.createWriteStream('test.txt');
for (let i = 0; i < 1_000_000; i++) {
  ws.write(Buffer.from(`${i}\n`));
}
ws.end(() => {
  console.timeEnd('streamWrite');
});
  • ⏱️It ran in ~270 ms, far faster than promise or sync versions!

🚧 Backpressure & Memory Issues

  • 🐏Naively writing every chunk risks overwhelming Node’s internal buffers, spiking memory to ~200 MB for 1 million lines (vs. ~50 MB sync).
  • ⚠️If you scale to 10 million, it can hit ~2 GB and crash due to “heap out of memory.”
  • 💡To fix, listen for writeStream.write() returning false (buffer is full) and wait on the 'drain' event before continuing.
