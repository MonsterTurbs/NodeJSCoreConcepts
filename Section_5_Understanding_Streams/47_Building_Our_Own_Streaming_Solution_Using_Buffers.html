📝 Study Notes: Copying Files Without Streams

🌟 Overview

  • 📂Goal: Copy a large file from “source” to “destination” without using Node.js streams.
  • ⚠️Copying in one go (e.g., fs.readFile + fs.writeFile) loads the entire file into memory.
  • 💡When files exceed ~2 GB, fs.readFile fails, and memory usage becomes huge.
  • 🔧This guide shows how to implement a manual “buffered” copy loop that reads & writes in chunks.

❌ Why Not fs.readFile / fs.writeFile?

  • 🔍fs.readFile() returns a single Buffer containing the entire file in memory.
  • 💾If the file is > 2 GB, Node throws “file size > 2 GB” error. Even smaller large files use huge RAM (≈ file size).
  • 🐢Example: Copying a 1 GB file with readFile/writeFile shows ~900 ms copy time but uses ≈1 GB RAM.
  • ⚡Desirable: Keep memory usage low (e.g., 30–50 MB) even for multi-gigabyte files.

🔄 Manual “Buffered” Copy

  • 📌Use fs.open to get file handles for source and destination.
  • 📤In a loop:
    1. Read a fixed-size chunk (e.g., 16 KB) from source via fileHandle.read().
    2. If bytesRead is zero → end of file, exit loop.
    3. Write exactly bytesRead bytes to destination via fileHandle.write().
    4. Repeat until entire file is processed.
  • 📉Memory usage stays low (≈ size of one chunk) instead of file size.

🛠️ Handling Partial Buffers

  • 🔍Last read often fills less than the full chunk size → leftover zeros in buffer.
  • 🧹Solution:
    1. After read(), check bytesRead vs. buffer.length.
    2. If unequal:
      • Find index of first zero: buffer.indexOf(0).
      • Create a new buffer of that “actual” size: Buffer.alloc(actualSize).
      • Copy only those “actualSize” bytes: buffer.copy(newBuffer, 0, 0, actualSize).
      • Write newBuffer instead of the full fixed buffer.
    3. Otherwise, write full fixed-size buffer.

💻 Code Example

const fs = require('fs/promises');

(async () => {
  // 1. Open source & destination
  const srcHandle  = await fs.open('text-gigantic.txt', 'r');
  const dstHandle  = await fs.open('text-copy.txt',   'w');

  // 2. Prepare a fixed-size buffer (e.g., 16 KB)
  const CHUNK_SIZE = 16 * 1024; // 16 384 bytes
  const buffer = Buffer.alloc(CHUNK_SIZE);

  let bytesRead = -1;
  while (bytesRead !== 0) {
    // 3. Read a chunk from source
    const { bytesRead: n, buffer: buf } = await srcHandle.read(buffer, 0, CHUNK_SIZE, null);
    bytesRead = n;

    if (bytesRead === 0) break; // end of file

    // 4. If last chunk < CHUNK_SIZE, trim zeros
    let toWrite = buf;
    if (bytesRead < CHUNK_SIZE) {
      const cutOff = buf.indexOf(0); // find first zero byte
      if (cutOff > -1) {
        const newBuf = Buffer.alloc(cutOff);
        buf.copy(newBuf, 0, 0, cutOff);
        toWrite = newBuf;
      }
    }

    // 5. Write exactly 'bytesRead' bytes (or trimmed buffer) to destination
    await dstHandle.write(toWrite, 0, toWrite.length, null);
  }

  // 6. Close file handles
  await srcHandle.close();
  await dstHandle.close();
  console.log('✅ Copy completed!');
})();

📊 Performance Comparison

  • ⚡**Method A (readFile/writeFile):**
    • ✔️ Copy 1 GB in ~900 ms
    • ❌ Uses ≈1 GB memory (unusable > 2 GB, OOM errors)
  • 🔄**Method B (Manual buffered loop):**
    • ✔️ Copy 1 GB in ~2 s
    • ✔️ Uses ≈ 30–40 MB memory (just one 16 KB chunk at a time)
    • ✔️ Can handle very large files (10 GB, 100 GB…) without OOM
  • 💡Tradeoff: Slightly slower, but extremely memory‐efficient.

📌 Key Takeaways

  • ✅Use fs.readFile only for small files (< 50 MB). Otherwise risk high memory use or errors.
  • 🔨Manual buffered copy (16 KB chunks) keeps RAM low, copying gigabytes effortlessly.
  • 🚫Avoid loading entire file into memory; read & write in loops of fixed‐size buffers.
  • 📚Understanding buffers (byte arrays) and fs.FileHandle.read() / .write() is essential.
