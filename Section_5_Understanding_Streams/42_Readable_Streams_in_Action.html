📝 Study Notes: Readable Streams in Node.js

📖 What Is a Readable Stream?

  • 🌊A Readable Stream lets you pull data from a source in chunks (small pieces) rather than loading everything into memory at once.
  • 📂Common use: reading very large files (e.g., gigabytes) piece by piece to avoid memory overload.
  • 📚In Node.js, you often get a Readable Stream from fs.createReadStream(path) or from sources like HTTP requests, sockets, or other modules.

🛠️ Creating a Readable Stream

  • 📂Import the filesystem module: 
    const fs = require('fs/promises');
  • 🔄Open a file handle for reading: 
    const fileHandle = await fs.open('source.txt', 'r');
  • 📥Create the Readable Stream from that handle: 
    const readStream = fileHandle.createReadStream();
  • ⚠️Flag 'r' means “read only.” Always close the handle after use:
    • await fileHandle.close();

🔊 Listening for ‘data’ Events

  • 🎧Attach a listener to receive each chunk: 
    readStream.on('data', (chunk) => {
  console.log('Received chunk:', chunk);
});
  • 🔢By default, each chunk is a Buffer (raw bytes). You can inspect chunk.length to see its size.
  • ✔️When no more data remains, the stream emits 'end':
    • readStream.on('end', () => {
  console.log('Finished reading all data');
});

📏 HighWaterMark & Chunk Size

  • 🔢By default, fs.createReadStream uses a highWaterMark of 64 * 1024 bytes (64 KB). That means each chunk will be ~64 KB.
  • ⚙️You can override this by passing an options object: 
    const readStream = fileHandle.createReadStream({ highWaterMark: 400 });
  • 📊If highWaterMark is set to 400, each chunk will be ~400 bytes instead of 64 KB.

📂 Simple File Copy: Read & Write

  • 🔄Goal: Read from source.txt in chunks and write each chunk to dest.txt.
  • 🖨️Open read handle and write handle: 
    const srcHandle  = await fs.open('source.txt', 'r');
const destHandle = await fs.open('dest.txt',   'w');
  • 🔄Create streams: 
    const readStream  = srcHandle.createReadStream();
const writeStream = destHandle.createWriteStream();
  • ➡️Pipe chunks manually: 
    readStream.on('data', (chunk) => {
  writeStream.write(chunk);
});
readStream.on('end', () => {
  writeStream.end();
});
  • ✅After running, dest.txt matches source.txt exactly (size & bytes).

⚖️ Backpressure in Readable Streams

  • 🐏If you read faster than you write, data piles up in memory (internal buffer). That causes high memory usage or crashes.
  • 📉To prevent this, pause the read stream when the write stream’s buffer is full, and resume once it drains.
  • ⚠️Without pause/resume, copying a huge file (e.g., 90 MB or 10 GB) can spike memory usage to gigabytes.

⏸️ Handling Backpressure: pause() & resume()

  • ⏸️When writeStream.write(chunk) returns false, the write buffer is full. Immediately pause the read stream:
    • if (!writeStream.write(chunk)) {
  readStream.pause();
}
  • 🔔Listen for the write stream’s 'drain' event, then resume reading:
    • writeStream.on('drain', () => {
  readStream.resume();
});
  • 📊This keeps memory usage low, even when copying very large files in real time.

🚀 Copying a Huge File Efficiently

  • 📂First, generate a large file (e.g., 10 GB) using a writeMany script.
  • 🔎Then, in readBack.js, copy it using backpressure logic:
    • const { open } = require('fs/promises');
(async () => {
  const srcHandle  = await open('huge.txt', 'r');
  const dstHandle  = await open('copy.txt','w');
  const readStream  = srcHandle.createReadStream();
  const writeStream = dstHandle.createWriteStream();

  readStream.on('data', (chunk) => {
    if (!writeStream.write(chunk)) {
      readStream.pause();
    }
  });
  writeStream.on('drain', () => {
    readStream.resume();
  });
  readStream.on('end', () => {
    writeStream.end();
  });
})();
  • 📈Result: Memory stays low (~30–50 MB) even copying a 10 GB file in seconds. Without backpressure, memory would spike to gigabytes and crash.

📊 Monitoring & Benchmarking

  • ⏱️Use console.time() / console.timeEnd() around the copy logic to measure duration:
    • console.time('copyTime');
// run copy code…
console.timeEnd('copyTime');
  • 🔍Watch system resources (Activity Monitor on macOS, Task Manager on Windows, top/htop on Linux) to see CPU & memory:
    • CPU often sits at 100% on one core (Node is single-threaded).
    • Memory stays stable if backpressure is handled correctly.
  • 💡Copying a 90 MB file took seconds with backpressure, vs. crashes when not handling it.
