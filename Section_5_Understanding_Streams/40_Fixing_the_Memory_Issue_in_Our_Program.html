📝 Study Notes: Writable Streams & Backpressure

🔧 Context & Initial Setup

  • 🗒️We copied previous code and commented out old solutions to focus on the new writable-stream approach.
  • 💡Stream object was created via fs.createWriteStream('test.txt'), representing the blue “internal buffer” box from slides.
  • 🏷️We saw a memory spike (~200 MB) when writing a million lines without handling backpressure—now we’ll fix that.

📏 HighWaterMark & Buffer Length

  • 🔍stream.writableHighWaterMark shows the internal buffer size (default ~16 384 bytes).
  • ⭕stream.writableLength shows how many bytes are currently buffered.
  • 📝Before writing, writableLength is 0. After writing a 6-byte buffer, it becomes 6, matching the buffer’s byte length.

🧱 Filling the Buffer & Return Value

  • ⚖️When you call stream.write(buf), Node pushes that chunk into the internal buffer.
  • ✅If the buffer isn’t yet full (writableLength < highWaterMark), write() returns true.
  • ❌Once writableLength ≥ highWaterMark, write() returns false, signaling that you must wait before writing more.

📦 Allocating a Buffer Equal to highWaterMark

  • 🔢We created a buffer with Buffer.alloc(16384) (16 384 bytes) so that writing it fills the buffer exactly.
  • 📊Calling stream.write(fullBuffer) immediately returns false because the buffer becomes full.
  • ⚠️Writing more without waiting would queue extra data in memory, causing spikes & possible crashes.

🔄 Handling Backpressure: The 'drain' Event

  • 🛑When write() returns false, stop writing to avoid exhausting memory.
  • 📢Listen for stream.on('drain', callback): once the internal buffer empties (data written to disk), 'drain' fires.
  • ✅In 'drain' callback, resume writing—now safe to push more chunks into the buffer.

⏳ Refactoring Loop: Stop & Resume

  • 🔀Moved the write loop into a function (writeMany()), with let i = 0 defined outside so it persists across calls.
  • ⚙️Inside writeMany(), use a while (i < 1_000_000) loop and each write() increments i.
  • ❌If stream.write(buf) returns false, break from the loop—then wait for 'drain'.
  • 🔄On 'drain', call writeMany() again to continue from the last i value.

🏁 Ending the Stream & Measuring Time

  • ⏱️We start timing before calling writeMany() with console.time('writeMany').
  • 🔚Inside the loop, when i === 1_000_000 – 1 (last write), call stream.end(buf) to signal no more writes.
  • 🎉Listen for stream.on('finish', …) to know when all data has been flushed; then call console.timeEnd('writeMany') and close the file.
  • 🚀Result: ~300 ms execution, with memory usage ~50 MB (far better than ~200 MB before).

📊 Memory & Drain Count Explanation

  • 📈Memory monitored in Activity Monitor: drops from ~200 MB to ~50 MB after adding backpressure handling.
  • 🔢Counted 'drain' events: 481 times for a 7 MB file divided by 16 384 bytes per chunk (7 MB ÷ 16 KB ≈ 481).
  • 🧐Last chunk is smaller than 16 KB so no final drain; total write() calls = 482, drains = 481.

✅ Key Takeaways

  • 🌟Never write unconditionally once write() returns false; always wait for 'drain'.
  • 💧'drain' indicates the internal buffer has emptied and is safe for new writes.
  • ⚡Properly handling backpressure keeps memory usage low and performance high, even when writing millions of chunks.
